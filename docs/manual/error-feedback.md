# 报错反馈

左侧“报错反馈”用于向 `zzusp/night-bot` 提交产品问题，不是自动遥测。

1. 填写标题和问题详情，描述异常对象、时间范围、预期和实际结果。
2. 默认选择“不收集”：只根据填写内容创建预览，不启动 Pi、不读取现场、不调用模型。选择“由 AI 收集诊断”后，使用当前任务模型启动独立的 Pi `AgentSession`，不会接续分诊、Router 或任务执行会话。
3. AI 先定位相关消息、任务或定时任务，再按关联读取消息阶段计时、投递、路由和任务轨迹，并可检索、分页读取产品源代码及受限日志证据。源码只允许产品代码目录，排除配置、密钥、数据、技能和依赖；磁盘源码不保证等于当前进程已加载的版本。日志仅提取时间、已知错误码、耗时数值及产品代码位置，不发送任意日志正文。缺失或超出范围的证据须明确说明，不能把无结果当成没有问题。
4. 预览实际 Issue 标题和完整 Markdown。可手动修改，点击“更新预览”后会再次脱敏；修改后必须重新勾选确认。脱敏是尽力处理，不能保证任意文字都没有私人信息。
5. 单独确认后，服务端使用设置中已保存的 `GITHUB_TOKEN` 创建 Issue。需具有目标仓库创建 Issue 的权限；不会保存新凭据或自动扩大权限。

选择“不收集”，不会启动诊断、读取日志或调用模型。不收集生成的预览同样可手动编辑，并须单独确认才会提交 Issue。诊断没有 shell、通用文件读取、MCP、技能或发 Issue 工具。模型建议不能触发提交。Web 鉴权、同源和 CSRF 校验仍生效。

Pi 会话和报告只暂存在本进程内存中，最长 30 分钟；可撤销诊断并清除暂存，退出后其他登录会话不能读取。进程重启不恢复诊断，不重放提交。确认提交可能公开可见，已有 GitHub Issue 不会因清除本地暂存而删除。

网络超时或结果不确定时不会自动重新创建 Issue。先在目标仓库核对；页面“核对提交状态”只查询本地记录，不重新发送。明确的凭据/权限错误修复后，仍需重新确认。关闭 Host 会中止诊断、排空已开始的提交；已发出的请求可能已被 GitHub 接受。

## 调查与上下文

诊断沿用模型真实上下文窗口，不人为声明模型支持更大窗口。启用 Pi 原生自动压缩，预留约 20% 上下文，输出额度不超过该预留；压缩时机由 Pi 管理，不保证每次工具调用前都压缩。证据以 E 编号保存在本次诊断内存中，可在压缩后按编号重新读取。

单次调查最多 96 次证据调用、约 20 万字符证据、15 分钟。达到证据预算时尝试生成部分诊断并标明未完成；超时或取消会中止。Issue 草稿只附分析引用的必要证据节选，不倾倒全部调查记录。提交前仍需用户审阅、编辑并确认精确正文。
