# 每日工作日志

默认启用，在 Bot 所在服务器的本地时间每天 **23:59** 运行一次。设置页、`night-bot-settings work-log`、`night-bot-config work-log` 使用同一校验与版本检查入口；修改时间、时区或开关后正常重启生效。配置和环境变量见[Web 操作手册](manual/web-console.md#每日工作日志)。不向聊天或外部平台发送日志，不创建业务任务。使用当前配置的全局模型，通过官方 Pi 无工具接口做一次语义复盘；这会使用该模型的配额和计费，日志不会生成额外会话、记忆或技能。

## 文件与记录范围

便携安装固定写入 `data/work-logs/YYYY/MM/YYYY-MM-DD.md`；显式旧式布局写入 `stateDir/work-logs`。Markdown 首先呈现当天进展、次日安排、问题与阻塞的语义总结，再附可追溯事实清单。总结综合当天消息、真实任务决策和完成记录、普通会话回复、执行活动、已登记的次日提醒，以及已记录的问题/阻塞；聊天中明确提出的次日安排也可被归纳，但不得把建议或愿望写成已确认承诺。工作日志是私有业务资料，不是可丢弃的诊断日志，随离线备份保留；现有 `data/` Git 排除规则适用。

内容从业务账本和官方 Pi **已提交**条目提取并脱敏后，发送给已配置的模型提供商整理，不执行消息中的指令，不读取工具输入/结果、思考、系统提示或原始错误正文。创建/调整事项不会被写成已完成；模型响应次数不代表任务完成；提醒入队不代表外部消息已送达。未安排的未完成任务不会变成“明天必做”的承诺。没有消息、执行活动或工作记录的日期不生成 Markdown，即使仍有旧的未解决问题或未来提醒。

日志是**执行时刻的快照**，文件明确记录汇总截至时间，不包含执行后的未来活动；例如默认 23:59 运行不会预知当天最后一分钟。每个日期的现有文件只读保留，不因重启或改时间重写。单段业务文字最多 800 字符，每类最多展开 500 条并显示未展开数量。标题、正文和来源标识都经过已知凭据和常见敏感字段过滤及 Markdown/HTML 转义。保留的业务内容仍可能私密；不要把日志作为可公开材料直接分发。

## 语义复盘与降级

模型只接收所选业务事实，不获得工具。每类最多 30 条、每段最多 800 字符，总计最多 120 条，另按模型上下文窗口扣除输出与系统提示余量，以保守 UTF-8 字节预算限制整个输入（最多 48000 字节），各类轮流取证以免消息挤掉安排/阻塞；超出范围在日志中明确标识，完整事实附录仍按下述独立上限展示。每条总结必须引用本次输入的证据 ID，程序校验字段、长度及引用有效性；语义是否忠实不是程序可证明的，日志明确标注为模型归纳。推断单独标注“推断，待核实”。当时记录的阻塞不自动代表当前仍受阻。模型输入和落盘输出均经过秘密过滤。

模型不可用、30 秒超时、返回工具调用或输出校验失败时，只发布明确标注“未完成语义总结”的事实清单，不保存错误正文或半成品推理。该日期仍只保存一次，不在后台无休止重试模型。服务关闭会取消并排空调用，不在关闭后发布。崩溃前若尚未成功发布，重启可能重新推理，但最终日期文件仍不重复。

## 调度与恢复

- 初次启用从当天开始，不回填启用前历史。扫描每 30 秒检查一次到期，长扫描或进程繁忙可能延迟；不是秒级闹钟。
- 使用配置的 IANA 时区。夏令时跳过的时刻在当天下一次已过该时间的检查执行；重复时刻仍只生成同一日期文件一次。
- 已启用后停机错过的日期按持久检查点顺序补记，每轮最多 31 天，剩余日期由后续检查继续处理。补记不拿当前状态编造过去的阻塞/次日安排。
- 停用并正常启动后会保存停用标记；重新启用从当天恢复，不补写停用期间。修改 JSON/ENV 后未重启时仍使用原运行配置。
- 同一状态目录的进程内队列与跨进程锁串行执行。先发布完整 Markdown，再推进检查点。崩溃重启认已有文件，不重发、不追加重复内容。检查点损坏、读取失败或不安全路径失败关闭，诊断日志仅记录错误代码，后续检查重试。
- 私有目录和 POSIX 0600 文件，不接受可配置输出路径、符号链接或无关硬链接；只恢复本发布器的同日期、同 inode 临时链接。Windows 使用安装目录继承的 ACL，真实 Windows 文件系统行为尚需本机验证。
