# 会话文件统计的 SQLite 缓存

## 目标与选择

每个源日志文件对应一条独立统计记录；未变复用、变化后严格重算并替换，最终按本轮有效源集合汇总。单目录 JSON 会增加小文件，哈希分目录仍保留同等文件总量；选择项目已有的 Node SQLite，在 Web 私有缓存目录中保存可重建派生数据，不改业务账本和 Pi journal。

## 实施边界

- `data/cache/web-console-<channel hash>/evolution-usage-<identity hash>.sqlite`，沿用页面缓存的认证身份隔离；不保存正文、凭据、原始路径或事件 ID。
- 一张表：来源身份哈希、日志指纹、统计依赖指纹、规则版本、条目数、统计/覆盖 JSON、校验和、计算和使用时间。
- 来源键绑定受控日志路径和精确任务/Router generation/渠道身份；依赖指纹绑定来源库、授权 scope、资源匹配字段/版本及影响扫描的预算。变更规则必须升级规则版本。
- 仅缓存严格 `requireComplete` 解码、身份校验和完整扫描成功的结果。命中仍通过 `readNativeDigest` 读取真实字节；变化记录绑定本次实际解码快照的 `journalDigest`。
- 缓存保留原有 partial 原因、null、时间与去重语义；命中也消耗原有条目预算，来源不可读不得使用旧结果。首次读取、哈希 I/O 和变化日志的主线程解码成本仍在。
- 短事务集中替换/更新时间；不在异步文件读取期间持有写事务。采用现有每轮 128 会话及 32 MiB 元数据缓存量级限制留存，LRU 淘汰仅丢弃缓存；不能把本轮未扫描推断为源已删除。SQLite 自动回收删除页，不每轮做全库 VACUUM。
- 行级损坏退回严格重算；数据库整体损坏/不安全路径显式拒绝刷新并保留旧页面快照，停止 Web 后可删除对应缓存重建。不自动删除无法确认独占的数据库及辅助文件。
- Web 启动默认接线，停止先排空采集再关数据库。页面 DTO 缓存及正文实时授权保持不变，无模型调用、恢复、重放或发送。

## 验证

使用隔离目录、真实 Pi 持久化与 SQLite：冷/热统计一致、重启复用、变化单源替换、不重复累计、未提交尾/不可读/身份与授权变化拒绝旧结果、资源版本失效、partial 原因和预算复用、缓存损坏与 LRU、文件/辅助文件别名拒绝。默认 HTTP 接线核对数据库及命中。运行 Web 服务端相关测试和来源/import/native guards；不合并、不部署、不发送真实消息、不手动触发 CI。
