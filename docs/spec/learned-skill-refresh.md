# 学习技能刷新去重

运行时追踪显示，Host `skills` 刷新在多轮 Router 处理中可以占据主要耗时。代码中，已学习技能每映射一个条目都重复加载整个授权目录，并单独重读反思状态；物化前和发布前又各做一次。在同一份 Bot 共享记忆上，这些读取还要逐次获取磁盘锁。现有追踪不细分各 provider，不以本地回归推算部署环境的降幅。

保留会话启动、请求前、轮末的资源刷新。只把 Reflection 自己注册且在当前 actor 目录中胜出的条目改成批量鉴权、准备文件、写前复核、最终复核；已存在的私有文件仍校验内容和路径，无写入时无需写前复核。不跨刷新缓存授权或内容。外部文件和其他提供方继续经过原有授权检查，因为 watcher 与缓存 revision 不能证明文件没有变化，也不能代表动态 provider 的授权。

用真实 Reflection 和 Markdown store 验证锁事务数不随本批学习技能数增长，并保留无通知修改、撤权、并行变更和生命周期回归。
