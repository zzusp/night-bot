# Router 排期查询失败后的恢复

部分结清的会话若留下已配对的只读排期查询失败，严格检查不能通过；当独立新输入到达时，隔离旧批次的检查也会因工具不在允许范围拒绝。没有新输入时的旧告警仍有意义，不以隐藏告警代替恢复。

继续走现有单 owner 交接，只针对已提交、明确配对且参数为空对象的 `platform_schedule_list` 失败。该工具只读取当前会话的排期目录与绑定，不修改排期、不调度任务、不发送消息。不把失败认定为未执行或成功，不重放旧调用。普通续办、未知任务效果、通知、历史隔离及版本校验保持原样。

用真实 Host/Pi/SQLite 的合成输入验证旧批次保留、新来源实际结清、旧调用不重跑；不向真实渠道补发或重放消息。
