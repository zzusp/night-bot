# 结单按当前交办组织结果

同一个真实结单中，用户追加了「不用在本群重复发」。执行结果的 `summary` 同时写了没有重发以及没有发往其他渠道，`limitations` 再记一次不重发；Router 展开的交办却只有用于引用和去重的最早消息。对外正文把后续操作约束和未交办渠道当成结果。已部署的写作规则没有改变这两个事实来源。

- 对外引用继续绑定原消息；给 Router 的结单范围另带这个完成版本上已提交、来源当前有效的用户跟进。从 Host 保存的交办关联读精确原话，不拿 Router 改写的执行交接当用户原话，也不把历史来源当新指令。
- Work 的内部分栏保留：`summary` 只记录已完成的请求和会影响完成的缺口；操作约束与内部依据分开记录。Router 对照当前交办与实际通知回执判断哪些送达状态要说。未要求的渠道不列；已取消的发送继续不发；问送达或交付确实缺失时照实答。保留完整内部证据。
- 不加词表、第二套语义判断、发后改写或额外关卡；沿用现有完成事件、接收者、原生引用、账本回执与防重。以同类续办场景和必要交付缺口做回归；固定已部署版本后从真实 UAT `xxp-bot` 认证入口回读新产生的消息，隔离验证不算该项通过。
