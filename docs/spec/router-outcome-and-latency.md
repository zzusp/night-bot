# Router 结果巡检与压缩慢尾

- 现有周期巡检按结果事件 ID 核对当前有效结果、Router 收件行与原冻结通知，只把隔离、等待超过 10 分钟、结清却没冻结通知写到既有运行告警。不引入任务状态、调度或补发；原通知的发送未知仍由唯一的回读路径核验。同任务旧通知不能抵新结果。
- 后台压缩不用在每次新输入排队时取消。仅在 Pi 原分支追加业务消息、对应工具调用/结果、不可见审计和提交标记时允许继续；只摘要旧快照，保留之后的原始尾部。每轮动态会话状态是唯一允许追加的系统提示补丁，由 Pi 保存最新有效检查点；分支、上下文编辑、其余系统提示、工具/模型/设置变化或原生压缩使候选失效。仅空闲可采用，原 owner 先提交再刷新。新输入能直接处理时不等摘要；超过既有前台水位时复用可验证的在途压缩，失败或仍无足够空间时走原生前台预检。
- 不采用降低水位来掩盖重复调用，也不取消 Pi 的容量守卫或溢出恢复。合成测试验证是否少跑摘要、是否阻塞正常输入、原始事件能否继续读取；真实模型时延另算。
