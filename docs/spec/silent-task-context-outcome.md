# 静默补充的任务结果

UAT 一次已认证的原任务补充明确要求不发群。执行会话提交了候选验收结果，Router 仍取得同一完成事件的原群发送绑定并实际送达。`replyBindings` 为空不代表禁止 Router 回报。

在现有任务补充入口接收显式 `suppressChannelOutcome: true`，只允许 `preserve` 补充。在原任务账本随上下文版本保存该选择，不从自然语言推断权限，不改变普通补充、原任务、依赖和回执。同一上下文的完成、业务阻断及执行失败继续由 Router 结清或评估，但不提供渠道结果绑定；混有其他独立消息时分批，静默结果批不得调用渠道回复。旧回执不撤回、不重送。新上下文的普通结果仍按原合同处理。

不采用只改执行提示（Router 看不到该限制），不把所有 Web 补充静默（会吞掉正常回报），不直接删除结果事件（Router 仍要评估依赖）。验证使用现有 Host、脚本模型和假渠道；禁止用真实群复测。
