# 续办后的阻断结果回报

- 执行侧：用户要求的端到端验证仍是完成条件。没有现成环境不直接等于阻断；先用任务内隔离样本和环境完成能够独立验证的工作。只有实际缺少必需依赖、样本、环境或权限且没有安全路径时才提交阻断，区分本地结果与目标环境验收。旧调用不重放，未知退出码不补造。
- Router：旧代际隔离会把受影响任务及其当时的来源留在防重放围栏中。同一个任务的新真实续办仍可完成，但新的 `task.blocked` 在引用旧来源时也被拒。本次选择用当前已核实的 `task.resume` 来源承接新阻断结果，保留明确指定的群收件人但不再引用旧消息。使用阻断事件稳定去重，不解除旧来源留置。无有效新来源、旧结果、附件或不能确认当前结果时保持原拒绝。
- 不采用整任务解除留置（可能重发历史动作）、换 ID 重试旧来源（违反原保护）或部署真实业务候选作为本修复验证。以原 Host/Pi 和假渠道复现同会话续办、拒绝旧回复、阻断回报送达以及冷启动不重复。
