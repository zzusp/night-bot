# 排空故障与任务状态

## 目标及证据

任务执行会话排空失败后，账本仍正确保留 `drained=false`，但列表 SQL、详情及执行状态据此显示执行中；故障只进入内存恢复告警。旧作业无可证明终态时禁止重放的保护必须保留。

## 决策

1. 只改前端标签：不能修正列表过滤、会话状态及重启后的事实，排除。
2. 强制排空或写新的业务等待决定：会伪造生命周期证明、覆盖原决定或消费输入，排除。
3. 在现有任务账本记录独立的 `sessionFailure`，采用同会话/租约校验的 Host 命令；不动排空证明、业务决定、输入和作业收据。采用此方案。

已知排空失败显示任务等待中、执行会话失败，阻断项解释核验要求。错误仅使用固定码和固定安全文案，不保存任意异常正文。真实 `task.drained` 后清除本轮故障；旧租约不得污染新轮。JS/SQL 投影一致，安装期升级既有触发器并刷新派生索引，GET 不运行 DDL。未知作业结清和原业务修复不在此状态修复范围内。

## 验证与交付

真实 SQLite 冷启动/租约/未消费输入回归；状态投影和既有触发器升级；原生 Host 失败入口及 HTTP 安全投影；页面等待状态。通过后 PR 合并、以已合并源码部署本机，核对实际旧任务不再假运行且原防重放仍在。
