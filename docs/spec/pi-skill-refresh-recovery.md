# 冷启动技能刷新修复

Bot 已接收新输入并写入待处理队列，Router 的前一项恢复复查未走完，诊断为 `PI_OFFICIAL_SKILL_AUTHORIZATION_CHANGED`。该错误有多个抛点；本地复现了别的会话更新自己的技能目录时，全局代次导致的误判，现场没有足够堆栈区分同码抛点。原任务领取了新租约并接纳输入，Pi 在模型请求前报 `PI_SKILL_VERSION_NOTICE_PENDING`，因此又进入巡检。该停止条件错误地要求提示已写入历史或已进入先前渲染的系统提示。

技能目录仅受当前作用域及其祖先的变更影响；共享技能的版本变化仍对所有会话生效。资源发布继续核验实际作用域、正文和授权。版本通知通过 Pi 的请求上下文投影传给当次模型，同时保留原生历史通知；不透传新正文，不重试业务动作，不自动判断任务或消息已处理。

用并发的独立作用域更新复现资源刷新失败，并在真实 Pi 冷续接的请求边界改变已读文件，确认收到正确的版本通知，不回放旧调用。
