# Router 模型超时后续办

Pi 原生重试耗尽且 Router 原批次仍待处理时，将超时检查点及原事件引用写入现有 SQLite 会话账本。现有恢复轮询或重启恢复负责唤醒原会话，不新增定时器、队列或业务重试计数。继续使用已提交的 Pi 检查点、原批次与补充输入校验、既有 durable claim；不从已隔离历史批次重放。

Router 基于原任务结果和现有回执决定是否、如何回复；Host 不代写、不重跑任务、不为已冻结回复另建通知。未知副作用仍失败关闭；原通知发送状态仍由原发送和回读路径推进。原事件结清时清理待续办标记，换代也不继承旧会话检查点。

以脚本模型和假渠道验证真实 Task/Router/Pi：任务完成入箱，模型超时，Host 恢复调度在没有新用户消息时续原会话，最终送达一次。冷恢复与已冻结回复一并检查。
