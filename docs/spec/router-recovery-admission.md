# Router 轮末刷新与接纳恢复

UAT `5b75e937` 当前 Router 的复查先遇到 SDK 请求超时，随后模型成功调用复查工具，原留置记录写入 `defer`。同一批次的 `resources-turn-end` 在 `skills` 子阶段失败。下一普通批次含原消息和任务巡检，只有入队收据，未接纳；后续周期持续核对原入队，报 `PI_OFFICIAL_ACTOR_NOT_LIVE`。现场 trace 未留技能内部异常码，不能把该错误归到特定授权抛点。当前待办还绑定一条旧恢复尝试收据：即使重新尝试，同参数生成的同一命令 ID 也只返回旧收据。

在下一条已授权输入尝试投递前，只对上一轮末的资源刷新错误重做资源校验及官方 loader 发布；仍失败则保留待办并返回真实错误，绝不越过生命周期、持久化或其他策略错误。重试收据按失败前观察到的退避状态区分顺序尝试，同一次重试仍幂等；重复巡检没有新增事件，不再绕过原批次退避直接调度。复用现有周期与输入队列，不补发、不重放此前工具，不让程序代做 Router 的续跑判断。

## 开轮刷新失败后的新输入

现场旧留置复查因技能授权变化在模型派发前中止，随后的普通消息重复走到接纳检查却没有进入模型。前次修复只标记轮末刷新错误。本次在隔离 Host/Pi 中复现：开轮资源读取失败留下旧策略错误，下一条消息在压缩预检报 `PI_OFFICIAL_ACTOR_NOT_LIVE`，即使资源已经恢复也无法继续。

在下一条耐久待接纳输入进入 Pi 前按原阶段重新核验并加载资源。未通过新授权检查前保留原策略错误、不派发模型。排除直接忽略旧错误（会带旧资源进入压缩）和换代（扩大恢复范围，也不能修复同类竞态）。持续的技能授权变化沿用现有同批恢复退避，不改变其它故障的处置。
