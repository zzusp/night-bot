# 默认内置技能接入决策

## 目标与边界

将明确指定的官方 `skill-creator` 与仓库已有的 `work-log-writing` 作为默认、可按需加载的通用技能。保留私有技能覆盖优先级、官方 Pi 的资源授权与版本校验，以及单任务单执行会话。不改变定时日报生成器，不部署实例，不引入其他私有技能。

## 方案选择

- 采用现有 `NativeSkillFilesystem.bundledSkillDir`：随代码/镜像发布，保持原有最低优先级，不创建第二套发现器。
- 不采用启动复制到私有技能目录：会引入覆盖、升级和冲突状态，且可能触碰用户既有技能。
- 不采用手动配置 `skillDirs`：不能兑现默认可用，也不能解决镜像资源缺失。

## 必要接线与权限

默认 Host 的两种执行预设和官方 Pi 资源解析使用同一代码相对目录。portable 安装的数据根可能与代码根不同；首次集成测试证明，仅增加发现根会在官方资源投影阶段触发 `PERMISSION_CALL_UNBOUND`。内置公共资源应按代码依赖读取，不应在尚无模型工具调用时申请业务文件权限。

在模型文件系统中仅将固定代码内置技能根识别为可读公共资源；仍对真实解析目标执行私有状态和跨任务保护，写入维持业务审批与任务档案合同。官方资源解析继续走 scoped FS、当前 provider 身份/版本、安全路径和 actor 生命周期校验，不改为宽泛 Host 直接读取。

镜像只白名单发布两个授权目录，保持 data、账号、凭据和其他技能排除；提供 Python 3/PyYAML 离线工具依赖。上游脚本除两处行尾空白清理外保留内容，技能前部说明单会话替代流程、受控产物路径、静态查看器和非默认 Claude CLI 边界。

## 验证

使用隔离 portable/绝对根安装、本地脚本模型、两种执行预设验证默认目录、正文与引用读取；验证同名私有/自定义技能覆盖、现有刷新/撤销和文件权限回归。执行项目源码/导入门禁；镜像构建和资源读回独立记录实际结果，不以静态配置代替成功构建。
