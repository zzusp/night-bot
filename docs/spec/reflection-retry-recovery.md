# 自动复盘安全补偿

现场有三类失败：索引选择无效、准备期间共享版本变化，以及旧 `REFLECTION_INCOMPLETE`（输出未结束与写入检查点共用，不能回推现场阶段）。只修复自动复盘，不重跑业务、重置耗尽记录或迁移历史回执。

- **索引选择**：保留三组真实 ID 会让模型重复抄写长 ID、区分不同字段；放宽校验会把没查完当作没有覆盖；依赖供应商结构化输出会改变 provider 合同。改为单个短编号列表，编号在本次快照中唯一，同一条目的拆分页共用编号。Host 严格检查当页归属，仍以原 ID/版本回查正文。
- **并发冲突**：沿用原计划会反复撞旧版本，直接改旧计划版本会绕过正文与权限准入，所有失败都重新生成会重放未知或部分效果。只有已知并发冲突、计划无已发生或不明效果、且与保存的遗忘代次一致时，才在原扫描与三次尝试预算内从当前索引重新准入；旧效果继续按原身份处理。未带新代次字段的旧计划不扩大恢复范围。
- **审计**：分别记录 Pi 输出中断和持久化写入检查点，不保存模型原始失败输出，不凭旧错误码猜测效果。通过本地脚本 Pi + SQLite 复现冲突，验证后续实际入库、归档及无重复写入，并保留遗忘、未知与部分提交反例。
