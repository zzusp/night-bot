# Web 执行记录订阅 Pi 更新

保留既有 HTTP 历史、游标与长正文接口。浏览器对当前任务或 Router 建立同源 SSE；Host 订阅当前 Pi 会话的临时输出更新和实际落盘的提交，发送脱敏的临时快照或补读通知。只读订阅不启动或维持 Pi；重连先补齐历史，断开、慢客户端和停机要释放订阅。参考 [pi-web 事件流](https://github.com/agegr/pi-web/blob/432366bd510c72ce7b678a6cb1220f9cac1ed56c/lib/agent-event-stream.ts) 的快照、事件合并和积压处理，不移植原始事件或会话生命周期。

沿用认证入口、严格会话身份和已提交 journal 的工具配对。普通实时帧和心跳不读取记忆/Skill 正文。对已经展示的独立正文保留定期复核：外部 Skill 文件变更、过期、其他进程写入都可能没有 Pi 事件，不能仅靠进程内通知替代撤权。健康连接无已披露正文时不再定时读取整页；连接不可用时沿用既有串行补读。选择 SSE 而非转发原始 Pi 数据、也不让每个 token 触发一遍历史 HTTP 和正文验证。

验收覆盖实际 Pi 临时输出、提交后按游标补读、同源鉴权、断线和停机清理、正文撤权、旧页和滚动锚点。
