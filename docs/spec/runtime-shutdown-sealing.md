# 普通停机与离线封存分离

目标：恢复本机渠道部署，并消除普通重启对全部任务工作文件数量的依赖。

现场旧进程已经关闭 HTTP 和钉钉监听，但仍在 `TaskArchives.seal()` 的 `filesUnder()` 中计算哈希；一个任务包含 84,086 个文件和 10,452 个目录。任务账本、原来源和送达通知与停机前一致，不能将端口关闭当作进程退出。

方案比较：给停机扫描设超时会产生未完成封存且隐藏失败；把封存放到脱离 Host 的后台会越过安装锁和存储生命周期；采用从普通 close 移除全量封存，保留原业务/执行/通知/复盘排空、投影队列 join 和 SQLite 关闭，完整封存仍由既有离线 backup 命令显式执行。普通关闭后的目录是 live-projection，不能直接当成已验证离线备份复制。

验证：既有真实 Host 归档测试先核普通关闭不产生 seal，再经显式备份验证会话、附件、输出、恢复 hold、损坏及链接拒绝；保留关闭失败/未证排空守卫。部署后对同一安装实测正常 IPC 重启，核原来源/回执不变和两个渠道恢复。当前旧进程不会因修改磁盘上的新源码而取消正在执行的封存；不热改旧进程、不删锁、不伪造正常关闭。
