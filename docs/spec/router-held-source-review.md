# Router 恢复后复查挂起来源

`ROUTER_BATCH_NO_PROGRESS` 的留置继续隔离旧批次，避免堵住新输入。发布恢复代际及进程冷启动复用既有会话调度；同一 Router 先处理可投递输入，再主动复查看得到的留置来源，不需要新用户消息。复查是独立的受限业务轮，不属于无工具交接，也不重新投递旧模型调用。普通 Router 不得伪造复查包。

复查以原会话、来源、版本及挂起凭据为边界。Router 选择沿用已证实的任务/送达、继续处理未产生动作的原来源，或留置待查；Host 查验账本关联、严格提交的旧 Pi 日志和当前来源授权。Router 对照原请求与任务实际范围、依赖安排或完整直接答复，写明覆盖依据；进度、澄清、截断或缺证保持挂起。Host 提供当前依赖行、安排版本及同源安排审计（如有），仅校验事实快照、复查身份和版本，不判断是否符合原请求。

证据不足或模型没有有效判断时保留挂起。同一轮排空不重复递交该来源；后续冷启动的既有恢复入口可再次递交仍挂起的消息和当时的证据，不把上次暂缓当成永久结论。仅有挂起消息的活跃会话在启动时也会进入恢复；常驻恢复轮询不因此重复复查。不增设回执触发器、重试队列或调度器。已有冻结/不明发送继续按原投递机制处理，复查不发消息、不替任务标记完成。历史挂起与判断随账本保留，旧日志不改变，无数据迁移。
