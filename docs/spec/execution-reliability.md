# 执行可靠性与范围落实

## 范围与现状

基线 008a4e2，先复用 #158/#164/#165/#166 已有恢复与进度查询，不重做已上线能力。当前安装旧效果已按可能部分效果结清，原任务完成、Router 事件已消费；这些现场恢复不等于所有触发原因已修复。本次只修代码并验证，不直接操作安装或外部业务系统。

## 优先级与责任层

1. 人工答复：跟踪 service.respondHumanRequest → task.human.respond/wake → 原会话输入 → task_result。比较真实调度缺陷、测试模型读取旧历史、whenIdle 观察边界三个解释，用实际请求与持久终态排除；不靠增加 sleep 或降低断言。
2. 原生作业：跟踪注册、producer terminal、owner 生命周期、通知、job_output。优先复用当前 NativeJobs 与原生审计；区分已完成作业输出丢失、真正未知效果与未知历史作业。未核验的 killed 不改成功，不用外部进程快照替代终态。
3. 分诊与范围：在各层既有职责内修复表达及上下文。短回复不代替 Router 授权/任务调度；目标修订提供完整当前要求并移除失效要求。对自己未写的范围外并发变化，保持现值、不扩大任务。
4. 性能：仅按观测确认的重复准备、短作业额外轮询或串行独立读取减量；不新建调度器/缓存平台，不以当前仅有上下文体积推断全部延迟。

## 方案取舍

- 只扩写总提示词无法修复 Host 作业/续办故障；仅用于模型确有语义缺口的相应职责层。
- 自动消费未结事件、放开未知效果或无限重试会破坏副作用与来源合同，排除。
- 在既有 Host/Pi、工具与耐久收据上修复责任层，并补最短真实回归，采用。复用单 task/session，保留权限、取消排空和旧具体调用 noReplay。

## 作业终态方案决策

- 排除只延长内存记录寿命：不能覆盖 Pi 会话释放和进程重启，还会保留已释放 actor。
- 排除未知 job 自动重跑或把进程不存在当成功：会违反精确调用 noReplay 和 producer 终态合同。
- 采用已有原生 settled 收据的可选有界输出快照：与 producer 真实终态同一提交，复用既有输出保留预算与模型可见渲染，不保存 observer log、不创建新存储层。job_output/job_kill 在活记录不存在时只读取当前官方 actor 自己的严格已提交收据；缺原生 producer 终态仍拒绝，旧无快照收据明确显示输出不可恢复。job_list 继续仅列当前 registry，不加载历史来增加每轮上下文。
- 输出渲染抽到现有 runtime 下一个小型共享模块，避免 registry 依赖整个工具插件，也避免持久和实时输出各自拼接出现隐私或 stderr 差异。settled 新增可选字段，不迁移或重写旧 journal；旧代码不用于打开含新字段的新日志。
