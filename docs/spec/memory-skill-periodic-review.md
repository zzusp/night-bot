# 记忆与技能周期复盘

## 目标与决定

用户确认同时实施长期记忆/Skill 准入规则，以及清理、合并、拆分、更新的周期维护。唯一进度入口为 `docs/acceptance/memory-skill-periodic-review/goal.md`。

比较三种方式：仅定时全量检查会反复读取不变正文；仅任务结束复盘会漏掉跨条目重复与失效；采用事件触发局部维护与可配置的每周集中检查。周期是安装配置，不写入个人身份或固定业务时间。

## 实现边界

- 复用现有 memory store、共享 Bot namespace、工具外 Pi ModelRuntime、reflection 生命周期和 journal/租约；现有用户提醒 schedule 绑定业务会话并会向会话投递，不适合内部无工具维护，不把它伪装为真人请求。
- 记忆、候选、受管 learned Skill 分别保留其状态与来源，候选不能自动晋升。正式安装 Skill 仅作参考，不自动改写。
- 先审索引和来源/使用元数据，再按需读取相关条目正文；模型给出带目标、证据、原因的清理/合并/拆分/更新动作。证据不足的留为待核事项，不生成替代事实。
- Host 校验受控目标、引用、操作形状、原版本及输出内容；在现有记忆事务中原子提交记忆、受管技能状态和维护收据。维护不得创建业务工具调用、重放任务或扩大授权。
- 经验变更同步撤销派生技能/复盘正文的有效引用；原任务和 Pi 历史仍保留。审计只保留条目身份、来源与前后 hash，不额外保存被清理的原文副本。运行中使用的文件不移动或删除。
- 每周为默认间隔；支持禁用和配置周期，冷启动恢复到期检查，失败记录可见且不影响已完成交付。关闭时取消并排空模型请求，未提交计划不应用。
- 模型负责语义判断，程序校验来源/版本/权限和原子性，不宣称证据 ID 或 evidenceBacked 标志能证明结论正确。

## 验证

本地脚本化模型端点与真实 Host/Pi、Markdown store、冷恢复联合验证：统一准入、假设字段不落盘、无充分证据的 Skill 不保存、旧 key 更新、四类维护动作、来源/版本冲突、未知目标和提示注入拒绝、候选不晋升、失败/取消/停机恢复、定时触发与幂等。执行相关现有记忆/复盘回归和 `pnpm check`。不部署、不发送真实消息、不提交或推送当前已有大量改动的分支。
