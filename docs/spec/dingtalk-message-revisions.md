# 钉钉消息编辑与撤回

## 目标与边界

编辑或撤回不清除接收进度、不覆盖旧来源与 Pi 历史。只改当前可选渠道及既有中立版本/授权边界；不重置水位、不自动重放旧任务或已发生的外部效果，不自动取消或回滚已有任务。真实安装升级与真实渠道验收须另行授权。

## 决策

- 忽略同 ID 的正文变化会丢失用户修订，排除。
- 直接放松核心指纹或把旧来源改成新正文会破坏审计与授权绑定，排除。
- 采用渠道侧串行版本分配：发生差异时用同 profile 的精确消息详情确认当前正文与原作者，复用 Host 的 messageVersion/source 机制。完全重复与可证明的附件/引用展示补全仍不新增版本；迟到旧事件以当前详情为准。校验/读取失败继续保留恢复界。

撤回只接受当前绑定会话的原生 recall 事件，群聊/单聊均显式订阅。使用中立 retracted 标记生成新版本墓碑，既有来源在同一事务撤权；墓碑不进入模型分诊，也不作为业务指令。上下文只附加重建墓碑所需的作者、时间及撤回元数据，沿现有持久化和冷恢复补齐事务；原 ingress.json 增加仅含原生身份与时间的 pendingRecalls 待完成队列，与 deferredMessages 共用恢复下界及串行落盘；在冷启动及既有范围补拉前补齐，正式接纳后解除。它不建立第二套消息正文存储。原始版本、通知和已发生效果留存。

历史查询缺项或 not-found 不证明撤回，仍保留暂缓记录及下界。只在明确撤回被可靠接纳后解除对应暂缓项。离线期间未收到的撤回，不声称由消息缺失自动修复。

## 验证

使用真实 Host/SQLite/Pi 与 fake DWS，验证编辑、重复补拉、迟到旧事件、作者/会话隔离、失败不推进、冷恢复、撤回前后队列/授权与重复撤回；原水位和历史保留。运行相关渠道/路由测试与源码/导入/hash 守卫，不访问真实渠道或发送消息。

## 验证中发现的必要持久化边界修正

Windows 多次在 ingress.json 原子替换返回 EPERM；真实无删除共享的文件句柄可复现同一错误，具体现场占用者未识别。修改既有 atomicWrite 的 Windows rename 边界，只对 EPERM/EACCES/EBUSY 重试同一已写入并 fsync 的临时文件，最多 5 次、100 ms 递增等待；持续失败仍抛出原错误并保留旧文件，不删后重建、不放松路径校验、不转移数据目录。真实内核测试覆盖短暂占用成功和持续占用失败，不靠 mock 或吞错通过。
