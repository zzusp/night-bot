# 渠道原始文件交付

## 目标与已有证据

修复钉钉可下载 PDF 等附件被适配器格式白名单拒绝、Host 无通用文件材料形态的缺口。基于 main / fcb39ced89b12724b94b6a1be861b47964d5c02b；第一轮实际失败及反证保留于 docs/acceptance/channel-resource-processing/round-1.md，文档 PR #12 已由外部合并。

## 决策

保留现有图片、UTF-8 文本、XLSX 和在线 adoc 的已支持输出；其余已下载文件通过互斥的 file 形态交付，包含 Uint8Array、原始文件名及 MIME。Host 独立校验描述符、计算长度与 SHA-256，发布到只读 materials，以受控哈希名保留安全扩展名，并只向模型提供路径及元数据。临时下载仍由插件清理；模型不需要 vendor ID、DWS 或账号即可取得原件。在线文档空间中的普通二进制文件走同一交付形态。

比较：逐格式增加 PDF/Word 解析器只能覆盖已知格式且新增依赖；签名 URL 有凭据、过期和模型环境可达性限制；受控本地原件复用现有 Host 发布、工具权限及归档校验，满足当前目标，故采用。解析内容仍由现有工具完成，不修改 Pi，不自动执行文件或提升权限，不更改已有历史 unavailable 快照。

同步扩展 typed pathBindings 的 file.path 字段，保留精确字段清单、原始路径验证、来源/版本/作者/消息/字节哈希及 no-replay。文件名只作元数据和安全扩展名来源，不能控制目标路径。保留 8 MiB 上限和失败关闭，不将凭据或业务原件写入 Git。

## 范围与验证

1. 插件实际下载、路径/大小校验、原件返回及临时清理；原有文本/图片/表格继续回归。
2. Host 将真实文件字节冻结成材料并供正式 Pi 工具读取；验证非法描述符、超限、不完整、材料篡改及恢复不重取。
3. 便携路径与备份/归档验证新文件描述符可迁移，拒绝伪造或额外路径字段。
4. 运行相关原生集成测试、源码/导入/哈希守卫；在授权既有测试安装/群内进行有限 PDF 和通用文档复验，核对材料原件哈希、真实处理与业务终态。
5. 群回复只给用户可理解的结果，避免复述内部 taskId；保留首轮 unknown，不改账本、不重发原消息。若发现与本次文件交付相关的实际失败，在本范围内修复；无关旧恢复问题不扩展。

完成后新轮次集中归档到同一验收目录并提交 feature/channel-file-material-delivery PR；不合并、不正式部署、不触发 CI。

## 公开业务标记误拦与原交付恢复（2026-11-10）

原请求明确指定的验收标记与报告名后来被选为 taskId，发送器仅按同值内部身份拦截，导致正文和文件未交付。结清为 failed 只修了状态，尚未完成用户交付目标。删除业务标记会改变用户要求及冻结交付；全局豁免来源中出现的所有身份会放开作者/会话等真实内部身份；采用仅 taskId 与精确可信原始来源业务标记同值的窄豁免，仍检查其他身份及机制格式。准备阶段与发送阶段复用同一判定，Host 临时注入来源上下文，不改冻结 payload/digest。

仅通过已有本机 operator 显式恢复入口，对完整本地未发送证明逐字段复核并消费 CAS，再重新校验当前来源/任务版本/产物和正文；自动扫描不重发，未知网络结果只回读。沿原父件和两个原文件的串行队列，实际送达及文件字节回读才算本次完成，不重跑任务、改账本或生成替代文件。
