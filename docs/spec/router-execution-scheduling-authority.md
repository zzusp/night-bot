# Router 执行会话调度权

## 需求与责任

2026-11-12 用户明确 Router 对执行会话的完整调度权：创建、启动、停止、重新唤起等均不再要求安装操作者另批。当前作者白名单、人工问题 audience/时序校验、已结清效果后的私密新目标授权，以及取消/完成状态的硬拒绝会阻挡真实 Router。

## 方案选择

1. 继续补人工 new-action：只解决旧接口状态缺口，仍把 Router 调度交给安装操作者，排除。
2. 因 full 全局移除来源、运行身份、旧效果及调用审计：会混淆角色和业务权限、导致重放，排除。
3. 直接删除已结清效果后的全局新目标许可，不新增 Router 授权证明；真实 Router 负责执行会话调度，来源保留追溯而不按作者白名单二次审批。Host 将生命周期冲突处理成排空和同 session 转换；旧未知效果只限制对应效果和真实业务完成，不能拒绝启动会话进行核验。采用。

## 实施边界

复用 Router 账本动作、现有任务状态和官方 Pi 输入/会话，不增加协调角色或第二套执行链。认证 Router 的代际、任务所属会话和精确请求收据继续校验；这些保证真正执行该 Router 的动作。幂等重试不取消新租约，实际停止先 join 旧工具/进程，持久 pending 输入保留。依赖为 Router 自己安排的先后关系，不变成人工批准；Router 可重安排。旧 effect intent/call/closure 不改写，不静默重放。

## 验证

真实 Router 工具到 Host/SQLite/原 Pi session，覆盖不同原消息作者的调度、无新增人工回复的恢复、暂停/取消/完成后的重新启动、在途停止与冷恢复；结清旧效果后无需人工 new-action 能执行独立新调用，旧调用仍只执行一次。未结未知效果允许唤起核验，不能据此把历史未知结果宣称成功。保留伪造 Router/过期代际、错误任务范围、旧调用重放、丢响应幂等和来源追溯反例。不以普通工具 mock 返回替代真实会话终态。
