# 任务压缩保留验证进度

长任务既要保留用户要求的真实验收，也要记住已经做过什么，避免在续办时重复做中间检查。审核锁任务发生过一次超限，原会话实际完成过 Pi 压缩并继续调用工具；末次停止是供应方策略拒绝，两者不是同一个问题。现有单任务入口写入 `night-bot-task` preset，角色摘要却只看 `runtimeOwner`；任务没有这个字段，所以没有使用已定义的任务摘要规则。

借鉴 [Claude Code 官方的上下文与会话说明](https://code.claude.com/docs/en/how-claude-code-works#the-context-window)：摘要面向下一步，保留适用要求、已核实发现与未决事项；不用参考镜像的原代码或提示词。复用现有 Pi 角色摘要入口，以任务 preset 选择任务规则，保留目标、实际验收条件、证据入口、下一项待核验工作与未结收据。短任务不新增调用；不调整水位、不新增后台压缩或独立审核、不迁移 journal、不改授权或重试。单独堆执行提示无法填补已定位的摘要接线缺口；复制上下文或新增阶段会改变现有会话边界，无此必要。

用本地脚本端点产生普通上下文超限，实际走 Pi 原生压缩和原任务会话，核对摘要请求、原始 journal、压缩后实际读回及无重复写入。不使用现场数据，不重送被拒绝的请求。通过只证明接线、摘要进入模型和原会话续跑，不证明实际模型判断能力或现场故障已解决。
