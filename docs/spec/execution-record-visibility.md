# 执行记录可见性调整

## 目标与证据

2026-11-12，安装操作者要求查看工具业务路径和结果、真实待办卡片、所有工具调用及模型已返回的内部思考；不要求模型额外生成进展文字。最近三项任务均有 `planning/todos` 已提交回执，现有 Web 投影却只显示工具中的 JSON 输入；命令、作业结果和全部路径被过度隐藏。

## 决定

- 保持现有安装令牌认证、conversation/task/session 身份校验、严格提交检查与 revision 分页；不改 Pi 执行、任务权限或原 journal。
- 普通文件、命令、作业和网页工具公开已声明的业务输入及准确配对的文字结果，业务路径与网页地址保留。工具名全部展示；未知工具、独立 memory/skill 权限、孤立或冲突结果给出明确原因，不透传未获权正文。
- 展示 Pi 当前上下文内原有 text、可读 thinking、toolCall 和 toolResult，按原块顺序投影；思考默认折叠，不展示厂商签名或补造未返回的推理。系统指令、私有 custom/audit 及秘密不透传。
- 待办取同一任务会话最新已提交的 `planning/todos` 回执，独立于工具历史分页与压缩；成功提交前的调用参数不能更新卡片。保留模型实际状态，不用任务完成推断全部完成，不增加执行状态权威。
- 在共享 ExecutionHistory 展示待办卡片，覆盖任务详情「执行记录」及 Chat 内任务组。无待办回执不造列表；已提交空列表明确显示为空；撤权立即隐藏缓存内容。

## 最小验证

服务端回归覆盖业务参数、路径、错误结果、思考与签名边界、全部调用名称、成功待办与未提交/跨会话反例、分页保真；真实隔离 Host/Pi 验证只读查询不改变历史或调用模型。浏览器核对卡片状态、思考展开、输入输出、撤权、移动宽度与可访问性；不连接真实模型、不发厂商消息、不部署。
