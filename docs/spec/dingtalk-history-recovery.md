# 钉钉历史恢复去重

## 目标与已核实症状

当前渠道历史 API 完整返回，但同 ID、同版本的已处理消息因可选厂商标记、附件展示和引用元数据差异触发 `CHANNEL_MESSAGE_ID_CONFLICT`。恢复界不推进，网页只显示恢复中而隐藏补拉失败。

本次修复可选钉钉插件的已处理重复消息识别，以及 Web 的安全错误投影。不得改写冻结事实、来源、历史回执或恢复水位，不重放模型、任务或发送；不修改其他工作区的既有实现。

## 取舍

1. 放宽核心 payloadHash 校验：排除，会影响全部渠道、同版本内容变更和来源授权。
2. 清除游标、跳过冲突或重放旧消息：排除，会丢失待接纳来源或重复业务效果。
3. 插件内核对已 routed 的精确来源与冻结指纹：采用，仅消费有完整身份证据的历史重复项，其他情况保留原接纳及失败路径。

## 实现约束

- 复用 `dingtalk-ingress.js` 与插件既有 `acceptHistoryMessage`，不新增核心兼容层、schema 或依赖。
- 相同来源 ID、版本、作者、会话及资源稳定身份必须一致；只允许有证据的厂商展示富化，不将同版本正文、引用身份或提及变化变成重复项。
- 完全相同输入仍走既有 Host 接纳。需要兼容时只读查询持久来源；识别成功只调用既有 consumed，不登记来源、创建任务或调用模型。
- Web 只投影固定错误码和中文解释，不泄露原始错误、账号、目标、正文或厂商消息 ID；补拉失败保持恢复界，不能伪装已连接。

## 验证

复用插件测试夹具和 Web 健康场景：覆盖重复消费不重放、篡改失败关闭、持久 deferred 结清、完整补拉终态、HTTP 白名单、真实浏览器桌面/窄屏。真实安装仅做只读指纹验证，不注入消息或重启服务。执行项目源码/hash/import 守卫、Web 类型与构建检查。
