# 消息首答关联修正

2026-11-10；在当前工作树已有首答用途过滤修正之上实施。现行 UI/UE 规则仍以根目录 DESIGN.md 为准。

## 目标

首答取 Host 接收至该消息的最早可靠回复送达时间，不限制回复用途。附件明确绑定到任务时，共同任务回复也覆盖附件；仅明确无需处理且无需回复的分诊结果显示无需回复。其余未取得首答的消息区分等待处理、等待回复、等待发送、失败、送达未知及历史不足。

## 方案

1. 仅直接 sourceId 匹配：已证明会漏掉附件和任务共同回复，不采用。
2. 按当前 task.sourceRefs 或同批消息套用结果：无法区分回复后才补入的来源及任务旧版本，不采用。
3. 采用既有精确来源版本绑定、任务事件和命令收据中的历史任务快照。快照必须在回复准备前已提交，且任务、会话、需求版本一致；据此构建只读的通知—来源关联。不从正文、文件名或时间接近猜测，不改原通知、摘要、收据或执行链。

查询先选择消息页及其来源，只读取这些来源关联的任务通知、事件和必要快照字段；保留归档读取。缺少关联证据不伪造耗时，也不归类为无需回复。共同回复的终点可以共享，各消息仍使用自己的 receivedAt 计时。

## 验证

覆盖附件单页而主消息不在页中、历史及归档共同回复、回复后补入、旧版本、异会话、未知早期发送，以及无需处理/等待处理/等待回复/发送失败。真实 Host/HTTP 回归、隔离浏览器与构建验证；现场数据只读复算，不发送真实消息、不部署或重启。
