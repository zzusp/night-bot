# 隔离交接后的 Router 调度

旧代际的来源保护现在会沿 `task.sourceRefs` 扩散到后续调度。生产发布这一较新的任务在执行会话没有未结作业或效果，但仅因两条历史来源被保留为未知，当前 `resume`、`supplement` 和 `control` 都在 Router 入口被拒绝。三项较早的任务同时还留有各自的执行证据缺口，不能按同一结论处理。

- 保留旧轮无上下文重试、旧来源变更/外发及同一具体调用的防重；不删除交接、任务效果或历史。
- 任务调度不因任务 ID 或历史引用命中交接保护而整项拒绝，也不新增强制来源、审批或数据补丁。原调用、显式旧来源、修订、代际、幂等和任务执行层的保护仍生效；修改依赖仍沿用旧交接保护。
- 用真实本地 Host + Pi + SQLite、脚本模型和假渠道验证：新调度能继续原执行会话；显式旧来源、错版本、过期修订和受保护任务的依赖修改仍拒绝。此改动不启动真实生产发布，不替旧构建或查验写结论。
