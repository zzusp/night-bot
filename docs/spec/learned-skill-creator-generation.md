# 学习技能经内置 creator 生成

## 目标与证据

修复 #149。主线 `1eabcc8` 中，任务无工具复盘的 `lesson.skill` 和 Router 的 upsert 都由 `Reflection` 直接把步骤排成 Markdown。内置 creator 已可供普通任务加载，但这两条生成路径没有加载或应用它。现有技能和私有安装目录不迁移、不补写历史 creator 记录。

## 决策

比较三个方案：仅在 Router 提示词要求先加载，无法覆盖自动复盘且 Host 无法证明生成；另开执行任务/AgentSession，会引入额外执行会话及调度链；采用独立的短生成阶段，复用 Pi 原生 Agent 循环，唯一工具实际读取代码内置 `skill-creator`，模型据候选、证据与旧版正文产出新 Markdown，Host 验证并发布。选择第三项，不开放复盘工具、不启动子代理或第二个业务执行会话。

生成阶段不具有文件写入、shell、任务调度或渠道能力。唯一 `skill` 工具只接受 `skill-creator`，读取本发行的内置资源，不受安装同名技能覆盖；实际工具调用及内容摘要、模型身份、输入/输出摘要随技能版本保留。未加载成功、非正常模型终态、秘密或无效输出一律失败，不回退步骤拼装。生成不声称完成独立 benchmark。

## 事务与兼容

慢推理在共享 evolution 锁外，发布前重核权限、来源、版本和遗忘代次。Router 仍按 operationId 幂等，已提交操作只修复当前派生文件，不重新生成或覆盖后续修改。自动复盘仍绑定原完成事件与合法 evidenceIds；失败独立记录，不回滚业务完成。更新正文也走 creator；删除、冷启重建和历史只读不再生成。Host 只添加 frontmatter、受管 scope 标记和来源，不用步骤模板替代生成正文。

## 验证与发布

使用真实默认 Host、SQLite 完成事件、本地脚本模型及受信 Router 流程：检查 creator 实际工具调用与后续模型请求、不同于候选的生成正文、发布读回、CAS、重复/冷启、失败和遗忘。回归复盘、Router 学习、技能加载/撤销和源摘要门禁；不调用真实模型或发送渠道消息。合并后按 Windows runbook 正常排空、独立发行部署，验收实际版本、健康、原任务会话和认证 Web。
