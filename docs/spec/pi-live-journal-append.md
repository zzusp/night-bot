# Pi 会话日志增量提交

分诊、Router、执行会话共享原生 Pi 会话存储。热路径原先在每次 `commit()` 回读并严格解码完整日志、逐条比较已提交历史；真正写入前还重建并解码整份候选日志。没有新条目也有全量成本。

继续使用当前 Pi 会话。打开、恢复与离线验证仍用严格解码；已打开的会话在取得 writer 租约并确认实际文件未变后，只检查和写入增量，沿用原有提交链及同步落盘。用 Pi 已提交条目的不可变性保护内存历史；用已知文件身份/状态拒绝异常替换，不把文件元数据当作内容证明，也不支持进程运行中外部编辑日志。无增量且分支不变时不读取日志正文；切换分支仍保存选中的分支。

方案比较：只合并请求准备的两次 commit 仍会反复扫描完整历史；完全取消检查会误把篡改或异常尾部认作已提交。采用共享存储增量路径，不改消息接纳、授权、审计、工具派发、恢复或磁盘格式。沿用现有共享 Skills 批量授权，另用默认分诊、Router 与任务会话覆盖两个改动的实际装配。
