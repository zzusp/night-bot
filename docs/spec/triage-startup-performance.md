# 分流首次请求与分项计时

## 范围

第一轮只做所选模型协议的本地预加载和分流内部观测。不改变模型、提示、资源刷新次数、持久化、权限和发送链路；不部署、不重启运行实例、不发送真实消息。

## 决策

- 在官方运行时发布会话工厂前，按耐久默认选择及显式运行时/记忆模型选择，导入 Pi 1.5 官方公开协议模块。只导入选中协议，不解析凭据、不发现远程模型、不发推理请求。无效/缺失配置仍保留现有延迟诊断语义；有效协议导入失败则阻止工厂发布。
- 分流由 Host 建立计时能力，传入官方会话创建、资源、输入和请求边界。阶段结束或失败时生成严格白名单元数据；观测异常不改变业务提交结果、不引起重放。
- 复用现有 observation 队列及 resident performance 分区。普通 SDK 事件继续验证实时 actor 身份；分流身份来自冻结的 conversationId/runtimeOwner 元数据。入队时捕获身份，避免 dispose 后异步处理丢失尾部观测。
- 无 taskId 的分流按真实 sessionId/groupId/runtimeOwner 查询，不伪造任务。旧投影缺少阶段字段时按空集合解释。
- 记录创建/挂载、资源刷新（指令、Skills、SDK reload）、输入持久化、请求 guard/commit/SDK prepare、提交与收尾。父子阶段及并行读取可能重叠，不得直接相加；SDK assistant 次数不是 HTTP 请求次数。

## 取舍与验证

选本地 import 而不发空推理；选现有性能分区而不扩大 SQLite source.stage 契约；本轮不做资源去重或会话池。用隔离目录、真实官方 SDK 和本地脚本模型验证预加载门禁、无网络副作用、分流持久观测及故障不重放。性能收益须在后续部署后的同口径测量确认，不能用模块热加载推断整链路降幅。
