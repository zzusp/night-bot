# 渠道长期偏好写入

## 目标与边界

修复已认证渠道用户明确提出长期行为偏好后，Router 只确认、只保留交接摘要而未写入共享长期记忆的问题。验收以真实 Host/Pi、渠道接入、Markdown 持久化、新会话读取和冷恢复为准；模型与外部消息运输使用本地脚本端点和假渠道，不发送真实消息，不部署或重放历史输入。

## 方案比较

1. 将整个 Router JSON 包当作用户消息：拒绝。混入任务事件、引用和交接内容，且不能为群 Router 授予全局写权限。
2. 仅恢复后台候选提取：不采用。候选未获接受，不能兑现用户明确要求的长期行为变更，也不能支持确认前核实落盘。
3. 增加原来源绑定的 Router 记忆动作：采用。Host 回查当前批次的原来源、作者、版本和渠道认证上下文，复用现有记忆服务、权限校验和事务存储；Router 的普通记忆权限仍只读。

## 实现合同

- Router 仅能提交当前已接纳批次中的直接原消息；不能从引用、任务结果或交接摘要获得写权限，不能跨会话、使用旧版本或借用其他作者。
- 只接受原消息明确授权的记忆请求或长期行为要求，保存准确原文及来源；临时要求不持久化，普通未来陈述不视作授权，秘密继续拒绝。
- 记忆写入绑定原发送者，而非群 Router 的合成身份；既有 read-only 权限继续生效，不整体放开群 Router 的 groupWrite。
- 成功收据来自事务存储并回读确认；失败须说明未保存，不能只答应“以后会记得”。偏好不必生成 Skill，任务复盘机制不变。
- 保存后的条目进入 Bot 共享记忆，可在其他已认证会话按需读取；既有原作者归因、去重、忘记和 no-replay 继续保留。

## 验证

以原报告文档偏好通过真实渠道接入驱动 Router 工具，独立解析落盘 Markdown，验证已接受而非候选、原作者/消息/引用哈希来源、新会话读取、冷启动保留及输入去重。补充跨会话/旧版本/引用冒用、普通和临时输入、read-only、写入失败的针对性反例，运行相关记忆与路由回归及项目 guard。运行安装原数据不改动；隔离实跑和当前安装已生效必须分开报告。
