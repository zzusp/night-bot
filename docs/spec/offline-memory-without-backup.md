# 离线记忆无备份升级

2026-11-13：本地部署最新已合并代码时，安装的 v3 记忆被 v4 Store 正确拒绝。官方迁移强制建立完整备份，与操作者已明确的本地不备份约束冲突；只读检查为 31 条、0 候选，尚未写入。

比较三条路径：保留旧代码不满足部署最新版；直接改版本/跳过备份步骤失去中断恢复与冲突证明；给既有离线入口增加明确的 `--no-backup`，仅处理当前需要的 v3→v4。

采用第三条：默认备份路径与协议不变。无备份只允许修改根索引、scope 元数据和退休的分类索引；单条正文、来源、候选及历史原件必须逐字节不变。若计划要求改写它们则拒绝。新版本迁移 journal 记录原文件哈希清单、必要的目标元数据写入及摘要，不保存原文件副本。正常完成后删除 journal、保留明确 `backup: null` 的完成收据；不能据此宣称可以回滚到 v3。

正常停机与安装/记忆锁、路径及链接检查继续复用。中断后仅凭原哈希或已规划目标字节认领文件，拒绝外来修改、缺失或新增文件；需显式重复 `--no-backup` 才继续既有事务，不更换既有事务的备份策略。旧有备份及回执不删除、不重写为无备份。

验证：CLI `--check --no-backup` 无写入；完整字段和正文保持；真实子进程中断后续写；源/目标/journal 篡改、运行锁和策略冲突拒绝；原默认备份迁移回归。验证后合并，重新拉取最新 main 准备正式发行，再执行离线检查、迁移和实际启动/原群恢复核验。
