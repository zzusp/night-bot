# 钉钉恢复接纳顺序

恢复时以最后接纳的消息时间（含重叠窗口）、更早的暂缓时间和既有恢复边界构造历史区间；没有接纳记录时沿用安装起点或既有完整范围。启动监听先取得覆盖保证，只缓存实时新消息；历史页完整、按时间进入原接纳链并提交范围水位后才释放缓存。普通增量不阻塞实时。原生撤回仍优先持久化，避免恢复期间旧正文复活。恢复缓存满时重新连接并覆盖丢失的实时范围，不提前放行；历史明确缺少作者证据的消息保留独立待核对状态。

不能先开放实时：它会改变接纳进度并让新消息插入历史批次。也不能完成历史后才启动监听：两者之间的事件可能漏收，尤其是无法靠普通历史列表重建的撤回。不能等模型结清全部历史后才接实时：慢分诊不是渠道缺口，身份未决的旧发送也不能无限阻断独立消息。放行条件是历史业务接纳已耐久，而不是 HTTP 请求返回或分诊推理已完成。身份不足的条目沿用逐条暂缓，不能冒充已分诊或盲重发旧通知。
