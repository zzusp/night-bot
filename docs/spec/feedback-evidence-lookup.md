# 反馈诊断证据定位

## 目标与现状

修复反馈诊断查询失败后无法继续、仅从最近消息定位而遗漏定时事项的问题。不修改用户业务任务、调度规则或正在运行的安装，不提交反馈 Issue。

运行版本 `71a7083` 的诊断捕获异常后只回 `query-failed`；discover 仅覆盖前 20 个会话各 100 条消息，最多三次检索，且 task 必须先从消息获得别名。原生 schedule 与业务 task 是不同实体，现有工具不查询 schedule。反馈原始调用参数未保留，无法反推 E1/E3/E4 的确切异常。

## 选择

1. 只放开消息扫描上限：仍找不到原生 schedule，排除。
2. 给诊断会话 Shell/任意日志读取：扩大私有数据和副作用权限，排除。
3. 复用 Host 只读任务查询、原生 schedule.catalog 和消息分页：采用。增加匿名 schedule 投影、按来源关联 task/message，以及可续查游标；查询失败返回固定错误分类与纠正指引，不公开原始异常。

名称、请求和调度指令只用于本机匹配，不传出正文。停止条件若仅存在于 prompt，不推断为结构化配置或已执行；明确标记未核实。标题与描述共同参与定位，候选不自动合并，不以无匹配证明不存在。复用现有反馈源码和测试文件，不新建运行时模块。

## 验证

覆盖短查询、无效别名恢复、消息窗口后的续查、独立任务/单次及循环调度匹配、单路故障不丢其他候选、隐私字段不外泄；用真实 SQLite 查询与原生调度目录验证接口，再经真实 Pi 会话验证结构化失败可见且可继续。保留现有 consent、取消、预算、私有 journal 所有权与无外发测试，运行源码守卫。

## PR 审查修复

原 offset 直接应用于每次重读的定时目录，周期到期排序变化会重复/漏掉候选；其他查询也会替换隐式检索词，使先前 continuation 指向错误的结果集。现在在单次调查内保存每个查询的精简候选快照，并用匿名 cursor 固定查询与分页参数；详情仍实时读取，已删除记录不伪装为仍存在。消息续查同样绑定原查询，标题/描述原文不放进 cursor 输出。无新权限或外发行为。

新增回归覆盖定时重排、任务归档移位、交错查询、跨调查/篡改游标和选中后删除；这些元数据快照仅存在于本次经同意的调查内。
