# 常驻会话后台压缩

一级分诊与 Router 的目标预算均为 500,000 tokens，实际预算取模型真实窗口与目标的较小值。正常窗口在 60% 的完整轮次结束后尝试后台压缩，80% 交由 Pi 原生前台压缩兜底；较小窗口或显式的大输出额度优先保留输出余量，水位相应提前。模型元数据中的真实窗口不被伪造为 500K。

后台候选使用独立 UUID、无业务工具与扩展的 Pi 会话，调用原生 compact()。新业务输入（含内部通知和定时触发）在入队时同步取消候选，不等待后台模型返回；忽略取消的迟到结果也不能生效。下一轮稳定后可重试。同一失败 checkpoint 不进行紧密重试。

接管不替换业务身份或重写历史。实现先验证输入代次、原叶节点、持久版本、条目数、模型、推理级别、工具、提示及设置均未变化，随后通过 Pi appendCompaction() 追加原生压缩结果，严格提交原 journal，再调用公开 refreshContext() 切换模型可见上下文。这个原生投影切换与替换物理会话达到相同上下文效果，但保留所有权限、审计、订阅、来源和 no-replay 绑定。提交期间的新输入可耐久排队，推理必须等待这段提交屏障，不等待后台摘要本身。

候选不在重启时恢复。只有已提交的原生 compaction 属于正式历史；持久化失败沿现有 store fence 停止使用，不能把不确定写入当作成功。已接纳消息的恢复与防重复仍由原 admission/journal 负责。

80% 水位与 overflow 继续使用 Pi 官方自动压缩，压缩开始即作废后台候选。对首次投递的大消息，使用 Pi 官方 token 估算提前压缩已有上下文，保留输出余量。单条消息或压缩后剩余历史仍超出可用预算时返回 PI_CONTEXT_INPUT_TOO_LARGE，消息保留在耐久队列，不截断、不声称已消费。估算不等于厂商精确计数，厂商 overflow 仍走 Pi 原生机制。

阶段观测包括 background-compaction、background-compaction-cancelled、background-compaction-adopted 和 foreground-compaction，记录耗时，不记录摘要正文。测试使用隔离 Host、真实 Pi SDK 和本地脚本化模型；不代表真实厂商压缩延迟，也不验证百部生产部署。
