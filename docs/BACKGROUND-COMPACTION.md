# 常驻会话后台压缩

Router 的目标预算为 472,000 tokens，实际预算取模型真实窗口与目标的较小值。正常窗口在 60% 的完整轮次结束后尝试后台压缩，80% 交由 Pi 原生前台压缩兜底；较小窗口或显式的大输出额度优先保留输出余量，水位相应提前。模型元数据中的真实窗口不被伪造为 472K。

后台候选使用独立 UUID、无业务工具、仅挂载纯角色摘要扩展的 Pi 会话，调用原生 compact()。新业务输入（含内部通知和定时触发）在入队时同步取消候选，不等待后台模型返回；忽略取消的迟到结果也不能生效。下一轮稳定后可重试。同一失败 checkpoint 不进行紧密重试。

接管不替换业务身份或重写历史。实现先验证输入代次、原叶节点、持久版本、条目数、模型、推理级别、工具、提示及设置均未变化，随后通过 Pi appendCompaction() 追加原生压缩结果，严格提交原 journal，再调用公开 refreshContext() 切换模型可见上下文。这个原生投影切换与替换物理会话达到相同上下文效果，但保留所有权限、审计、订阅、来源和 no-replay 绑定。提交期间的新输入可耐久排队，推理必须等待这段提交屏障，不等待后台摘要本身。

候选不在重启时恢复。只有已提交的原生 compaction 属于正式历史；持久化失败沿现有 store fence 停止使用，不能把不确定写入当作成功。已接纳消息的恢复与防重复仍由原 admission/journal 负责。

80% 水位与 overflow 继续使用 Pi 官方自动压缩，压缩开始即作废后台候选。投递先完成 admission 授权与去重，再使用 Pi 官方 token 估算预检；重复或已取消输入不触发摘要，预检等待后仍检查撤权、暂停与取消。活动 steer 也检查单包容量，但不在活动推理中调用手动压缩。空闲时，无论当前历史是否已越过前台水位，都按“已有上下文 + 新输入”决定预压缩并复核输出余量。

预算包含合并后的当前原生系统提示与工具声明，不重复累加系统增量；首次尚无系统条目时补计 Night 将注入的 sections、记忆提示与资源声明。首次资源权限检查在 Pi 接纳正文前完成，保持原资源权限边界。预压缩临时将原生 keepRecentTokens 限制为扣除固定提示、新输入后剩余额度的一半，另一半留给摘要；成功、失败或取消后均恢复原有效保留设置。压缩后的真实投影仍须通过容量复核，不保证不可切分的大轮次一定可压缩。Router 显式续办在领取失败 checkpoint 前累计检查 supplements 和两条控制正文。单条消息或压缩后剩余历史仍超出可用预算时返回 PI_CONTEXT_INPUT_TOO_LARGE，消息保留在耐久队列，不截断、不声称已消费。估算不等于厂商精确计数，厂商 overflow 仍走 Pi 原生机制。

请求级图片错误阻止不健康状态下的后台摘要，但不永久阻断下一次输入：新 agent_start 重新校验图片策略；历史图片仍超额时仍拒绝，不删除历史绕过策略。持久化和权限失败栅栏不放宽。关闭/取消时在原生 compaction_start 再次校验 owner，覆盖 Pi 尚未安装取消 token 的窗口；关闭先排空预检再移除订阅。

阶段观测包括 background-compaction、background-compaction-cancelled、background-compaction-adopted 和 foreground-compaction，记录耗时，不记录摘要正文。原生摘要调用不建立业务模型 span，也不占用前一包或后一包的 runId。测试使用隔离 Host、真实 Pi SDK 和本地脚本化模型；不代表真实厂商压缩延迟，也不验证百部生产部署。

## 角色摘要

Router 的手动、阈值自动、overflow 及后台候选通过公开 `session_before_compact` 接入同一角色说明，使用原 preparation、原生 `compact()` 与当前 Session 的认证流；不另建 HTTP 调用或历史映射。Pi 仍负责近期保留、split-turn、文件引用、appendCompaction 和上下文投影，水位与输出余量不变。角色扩展失败明确取消压缩，不能静默回退通用摘要。

Router 保留有效目标、纠正、任务/依赖/动作收据引用、未决问题与承诺、下一步查询入口；进度和送达状态只是当时观察。Router 同时保留目标范围、完成条件、可选验证的待确认/已确认状态、执行顺序及既往明确要求的来源引用，不能把建议变成新完成门槛。摘要要求新修订替代旧状态、prepared 不冒充 delivered、长期指令只保留 ID/版本并以当前必载列表为准。split-turn 仍是 Pi 原生两段摘要合并；提示要求指出替代关系，不声称能强制任意模型永不保留矛盾。

原生 retry 设置继续传给 compact helper；扩展没有调用 Pi 私有 summarization retry callbacks，故不保证 SDK 的逐次摘要重试事件与默认内部实现相同。既有前台/后台阶段、候选取消/采纳和耐久屏障继续保留。脚本端点测试可以证明请求接线、生命周期和防重放，不能证明真实模型的摘要质量或提速幅度。

原生 overflow 可能把当前 custom business input 一并纳入摘要。后续请求若看不到当前已接纳 packet，应用仅在系统 section 提供这份准确原文的只读引用；packet 仍须处于 admitted，原文已可见时不重复附加，不执行 enqueue/deliver 或改写 journal。引用不表示再次交办，已结动作和最新状态仍按账本处理。Router 不能靠摘要猜测本批原话，也不能把旧来源当作新输入。

旧分诊 journal 的既有压缩记录只读保留；新消息不再创建分诊会话或分诊压缩轮。

Router 私有模型的未声明窗口兜底提案：仅在模型没有显式 `contextWindow`、provider 没有显式 `defaultContextWindow`、Pi 内置目录也没有该模型窗口时，Router 使用现有目标常量对应的 472,000 窗口；任务执行及其它角色仍使用原 262,144 兜底。Router 与执行使用隔离的原生 SDK 目录，不更改全局目录；新建及恢复均按原角色解析，前后台压缩和只读卡片使用该会话实际生效的模型窗口。显式值及 Pi 内置窗口（包括更小的窗口）始终优先，比例和输出余量规则不变。

未声明窗口不代表供应商支持 472K。此兜底只是部署者的容量假设，可能让较小私有接口在旧阈值之前已超限；已知较小的接口应显式配置 `providers.<id>.models[].contextWindow`，或 provider 的 `defaultContextWindow`，保留其真实限制。该提案不探测或验证供应商，不改任何运行配置；当前运行不受影响，代码采用及按原流程重启后才会重新解析。不要以调高目录元数据冒充真实供应商能力。
