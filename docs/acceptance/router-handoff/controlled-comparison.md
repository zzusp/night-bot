## 冷暖与仍保留的准备成本

两边都是首次真实 create、后续实际同一 SDK actor、Host 关闭后在原 Pi session 上真实 resume。每边 Router create=1、resume=1；暖消息未重建 SDK，没有空队列推理或保活请求。这是 SDK/Host 冷启动隔离，不是新 OS 进程、远端 TLS 或厂商缓存的冷启动试验。

该次候选两次 session-sdk-create 约 0.47–0.63 ms；暖 handle 没有该阶段。before-run 约 21–66 ms、技能准备各样本约 8–153 ms、system-prompt 约 2.4–3.2 ms、request-prepare 约 5.5–25 ms。它们不是会话新建，更不是供应商首输出等待；阶段可能嵌套，不能相加。脚本端点 model-started 到首输出约 5–12 ms，不代表现场 85 s。没有证据支持改保活、预热、压缩水位、后台策略或缓存掉有版本/权限语义的准备，因此未修改。

新增固定元数据阶段 router-reply-lookup/review/register，分别界定通知查询、保留的正文复核和登记；该次复核约 151 ms、登记约 8.3 ms。工具其余验证、排空、调度、发送、回查仍按原边界，不把剩余时间叫空闲。未回填历史 12.83 s 的分段。
