# 第三轮：原收件人回发与入库清理

基线 `ec130885f18b551c3e1908b700937421b09186bf`，分支 `worktree-file-recipient-cleanup`。下述结果来自该基线叠加本轮工作树源码及测试的实际执行；Linux 容器只读挂载实时源码和测试，不将旧基座镜像版本当成本轮验证版本。仅使用合成文件和假渠道；未调用真实钉钉发件，不读取或删除历史业务文件。

- **回发**：原请求作者与本次请求作者不同的私聊，实际唯一对端为原作者。真实 Host 冻结父子通知并独立读回，附件 SHA-256 与原件一致，原任务的完成记录不变。同作者、重复入站、第三方、跨会话、错版本和不在已报告路径内的反例保持原边界；离线封存后篡改来源作者或受众均被拒绝。
- **入库与清理**：只入库仍能直接读取旧原件，第二模拟渠道读取相同文件 ID、版本、字节。明确要求清理的合成请求在 Linux `ask` 模式沿原执行会话运行，核对 SHA-256 后删除，独立读回 `ENOENT`，指定旁文件仍是原内容。Windows `ask` 的受限 shell 不在已支持范围，本轮定向用例在 Windows 跳过；未改日志完整性校验、受限进程策略或权限模式。
- **模型判断**：约定的 `cortex-cowork` 经真实 Router 决定回发，模拟附件仅发给原作者，摘要匹配。独立复验导入时核对了原件 SHA-256，持久任务记录显示原执行会话收到含精确路径和摘要的清理交接，没有额外可见性门槛。这两个模型用例使用合成输入和假渠道，清理实跑另由 Linux 脚本模型用例证明。
- **检查**：`pnpm check`、`git diff --check` 通过。路由完整组 259/259；最终 Linux 附件、知识库及钉钉适配器定向 61/61，受限容器不挂业务卷、不接外网。首次 Windows `pnpm test:runtime` 146 通过、8 失败、12 跳过；独立主线复验重现其中 7 项（两项定时汇报、四项人工答复、一项长续接）。另一个 PDF 用例在本轮触发脚本模型未准备的摘要请求；为该用例补齐摘要应答后按原业务断言单独复验通过。

## UAT 边界

本地及模拟渠道结果不代表真实钉钉送达。此轮记录时 `db-dev/xxp-bot` 仍运行第 130 代旧镜像。真实业务验收需要在已授权的原私聊由两侧正式认证入口使用合成请求、同会话下载附件并核对 SHA-256；另一正式渠道读回入库版本及字节；钉钉客户端实查枚举、字段和路径的渲染。未用管理员数据接口、历史原件、人工代发或健康探针替代这些结果。
