# 日常使用

以下操作发生在你自己的 Web 控制台中，不是本静态网站。先完成[安装与启动](./getting-started)，再验证实际模型可用。

## 先让 Bot 适应你的业务

上手优先配三处，而不是每次发任务都重讲一遍：

- **渠道提示词**：在「渠道 → 编辑配置 → 渠道职责」写这个渠道管什么。比如支持群处理客户报障，项目群跟进迭代，两个渠道可以各写各的。
- **Router 工作原则**：在「设置 → 工作原则」写怎么接活和回报。比如同一故障沿原任务继续，有核实的结果再回报。
- **执行会话工作原则**：同在「设置 → 工作原则」，写任务怎么做、怎么验收。比如先确认环境和运行版本，再查故障时段日志。

先挑一件你常提醒 Bot 的事，放进对应位置，再用小任务验证。临时要求仍直接发给当前任务。见[配置示例与生效时间](./configuration#工作原则)。

## 发起任务与补充信息

在「与 Bot 对话」输入目标、材料和限制。Enter 发送，Shift + Enter 换行；中文输入法确认候选不会发送。

可从小而明确的任务开始：

网页对话可以粘贴截图、选择文件，也可以只发附件。任务已建好时，到「任务详情」底部补材料或改要求，消息直接进入原执行会话，不另开任务。已完成但仍可编辑的任务也可以这样继续；从这里补充的结果不会自动发回原外部渠道。每条消息最多 8 个非空文件，合计不超过 8 MiB。图片能否由模型直接识别，还取决于所用模型。

**“已接纳”只表示消息已收到。** 任务状态和实际回复仍会继续更新。发送中断时保留草稿，先用「核对发送状态」检查原请求，不重复提交。关闭页面不会取消已接纳的工作；未发送草稿只在当前标签页内存中，刷新或关闭可能丢失。

## 看清任务进度

「任务」每页 10 条，分为「未在执行」「执行中」「已完成」「已取消」；「全部」清除状态筛选。「未在执行」可能是待调度、已暂停或中断，具体原因看任务详情。

「已完成」表示这一轮正常结束，不保证每项要求都办成，也不代表结果已经送达。看详情里的结论；已取消的任务可以查看取消原因。

渠道新消息直接进入该会话的 Router，没有单独的分诊或自动收悉。页面上切到「路由」看 Router 怎样处理；看具体任务的执行记录、结果、耗时和复盘统计，去「任务详情」。工作动态只看当前打开会话的关联任务。

任务完成不会自动授权后续动作。执行成功、结果发送和收件方实际收到也要分别核对；未知效果应保留现场，不能用重发来试探。

## 处理权限审批

认证安装操作者可在「权限与审批」查看 Host 报告的模式、保护状态和待审批动作。

- 核对动作、目标、工作目录和范围，再决定是否批准此次。
- 批准只绑定原调用与参数，不成为对其他动作的长期授权。
- “已批准”不是“已执行成功”；实际结果仍查看任务记录。
- 撤销只适用于尚未消费且仍有效的授权，不回滚已经发生的效果。

当前新安装默认 `full`，不提供工作区或进程隔离。已有显式 `ask` / `auto` 不改变；受限后端不可用时拒绝执行。详见[权限与安全](./security)。

## 记忆、技能与定时工作

Bot 共享长期记忆，并保留来源和读取权限。你可以要求记住、纠正或忘记信息；模型推断不应当作已确认事实或授权。

在「自进化」查看有权限的记忆和 Skills。要改 Bot 管理的内容，在对话里说清要改哪一条、改成什么。记忆可改标题、索引说明和正文，学习 Skill 可改名称、说明和正文；它不会改写你自己安装的 Skills。

任务复盘只留下下次还能用的已核实经验，不把每一步操作都记下来。自动整理默认关闭；要用时按[自进化维护说明](https://github.com/zzusp/night-bot/blob/main/docs/SELF-EVOLUTION.md#事件与周期维护)配置。

定时工作支持单次、固定间隔、每日、每周和五字段 cron。描述时说清执行内容、时区、时间和允许的动作，并核对实际保存的排期。停机恢复会处理到期事项，周期事项合并漏过轮次，而不是逐次补跑。

## 报错反馈

在控制台打开「报错反馈」，填清发生时间、操作步骤、实际现象和预期结果，不填账号凭据。可以只生成预览，也可以选「由 AI 收集诊断」。诊断失败时，已有证据可能保留为未完成草稿；没有证据时会显示可公开的失败原因和诊断编号。

先检查、编辑预览，再确认提交 Issue。需要附截图时，选「在 GitHub 添加图片」，先遮盖敏感内容，再到 GitHub 手动添加和提交。Night Bot 不会读取或上传这些图片。详见[报错反馈手册](https://github.com/zzusp/night-bot/blob/main/docs/manual/error-feedback.md)。

## 常见问题

**服务健康，但没有模型回复**：健康接口不验证模型。检查路由、模型 ID 和对应凭据状态，不要重发已接纳的请求。

**Web 提示资源未构建**：在相同代码版本的 `packages/web-console` 安装依赖并构建，不必把它解释成核心未启动。

**页面断线或会话过期**：先恢复连接或重新登录，再只读核对状态。网络故障不表示原操作没有执行。
