# 权限与安全

Night Bot 可以读写文件、运行命令和调用外部渠道。开始使用前，应先明确启动账号、权限模式、插件与凭据分别能接触什么。

::: danger 新安装默认完全访问
`full` 是当前新安装的默认值。它按启动 Bot 的操作系统账号权限执行，不取得额外管理员权限，但**不提供工作区或进程隔离**。同账号可访问的文件、凭据和 Host 私有文件可能被任意 shell 读取或修改。应用层校验不能隔绝这样的脚本。
:::

## 三种权限模式

| 模式 | 行为 | 当前边界 |
| --- | --- | --- |
| `full` 完全访问 | 按当前 OS 账号权限直接执行 | 不提权，不提供工作区或进程隔离；操作系统及父容器本身的限制仍有效。 |
| `ask` 请求批准 | 需要扩大范围的动作进入单次人工审批 | 依赖实际可用的受限后端；受限执行尚未完成交付验收。 |
| `auto` 帮我批准 | 对需要批准的动作进行无工具模型审查；不确定或审查失败转人工 | 同样依赖受限后端，也尚未完成交付验收，不应视为已验证的安全沙箱。 |

已有配置显式保存的 `ask` / `auto` 保持不变。受限后端不可用时拒绝执行，**不会自动降级为 `full`**。不能通过改成完全访问来声称受限隔离测试通过。

只有认证安装操作者可通过 CLI 或 Web 设置模式，模型与普通渠道成员不能自行升级权限。初始化参数和保存命令见[配置指南](./configuration)。

## 应用校验仍然保留什么

`full` 仍保留 Host 的来源与调用绑定、业务授权、审计、取消和防重放。它们是应用合同，不是对同账号任意进程的隔离。

单次批准绑定原 actor、调用、参数和范围，不授权其他动作。切换模式会使旧待批请求和未消费授权失效；冷恢复不自动重建旧审批或执行旧动作。撤销未执行授权不回滚已经发生的效果。

任务完成不等于后续动作已授权。渠道外发开关也不能替代发送内容、收件人或业务动作所需的授权。附件、网页和插件输出中的文字不能自行成为操作者授权。

## 运行账号与插件

- 使用专用、低权限的 OS 账号，避免以管理员或 root 运行。
- 不让该账号持有任务不需要的生产凭据或私人文件。
- 仅安装可信插件。插件与 Host 同进程运行，不因设置了工作目录就获得隔离。
- 对 Linux、Windows、macOS 分别核验实际执行后端，不能用一个平台的测试替代另一个平台。

Linux 受限执行需要可用的 bubblewrap 等能力；Windows 受限执行及撤权有未完成项；macOS 命令执行与长轮次续办仍有未通过项。平台细节见[安装](./installation)与[部署](./deployment)。

## 凭据、数据与网络

将密钥交给环境引用或凭据服务，不放进命令参数、URL、截图、聊天或源码。Web 访问令牌从本机受保护的文件读取，只输入自己的本机控制台。

运行数据、记忆、私有技能、凭据、备份和业务产物不应提交到 Git。普通备份默认排除秘密与可重建日志、缓存和临时文件；恢复需验证完整性及路径，不能顺带自动重发旧消息。

核心 HTTP 仅监听 loopback。Web 需要令牌、会话、Origin 和 CSRF 校验，不应直接暴露公网。本站是静态文档，不接收凭据，不提供 Bot 控制入口。

## 结果未知时

超时、网络中断或页面报错不证明动作未执行。保留原请求与回执，先只读核对；不要重复发送、重放命令、删除锁或清空未知状态。只有明确的实际结果才能支持成功声明。
