# Night Bot

[官网与文档](https://zzusp.github.io/night-bot/) · [快速开始](https://zzusp.github.io/night-bot/guide/getting-started.html) · [使用教程](https://zzusp.github.io/night-bot/guide/usage.html)

基于 [Pi](https://github.com/earendil-works/pi) 的个人助理 Agent 初始化套件。

把任务交给自己的 Bot，通过可选的 Web 控制台或消息渠道持续协作。Night Bot 将任务执行、长期记忆、技能学习和定时工作放在同一个运行环境中；渠道负责接入，核心可以独立、无界面运行。

Pi 负责模型与工具迭代、会话历史和模型上下文。Night Bot 在此基础上管理消息路由、任务生命周期、权限、恢复与交付。当前使用锁定的 Pi 1.5.0 SDK，不是 Pi CLI 的封装，也不要求先安装 Pi CLI。

## 让 Night Bot 按你的业务方式工作

**模型和渠道接通后，先配这三处提示词，再交第一个业务任务。** 这是 Night Bot 和只提供一份全局提示词的 Bot 的区别：每个渠道能有自己的职责，接活和执行也能各有一套规则。不用每次交办都重讲背景、跟进方式和验收标准。

| 先配哪一项 | 在哪配 | 写什么 |
|---|---|---|
| **渠道提示词** | 「渠道 → 编辑配置 → 渠道职责」 | 这个渠道服务谁、处理什么。例如：只跟进本群编辑器的生产故障，闲聊不介入。 |
| **Router 工作原则** | 「设置 → 工作原则 → Router 工作原则」 | 怎么接活、跟进和回报。例如：同一故障沿原任务跟进，有核实结果或明确卡点再回报。 |
| **执行会话工作原则** | 「设置 → 工作原则 → 执行会话工作原则」 | 任务怎么做、做到什么才算完成。例如：先确认环境和运行版本，再查故障时段日志。 |

每处先写一两条平时会反复交代的要求，再用真实场景的小任务验证。一次性的要求直接发给当前任务；提示词不授予权限，也不要写入凭据。见[配置示例与生效时间](website/guide/configuration.md#工作原则)。

## 能做什么

- [Bot 共享知识库](docs/SHARED-RESOURCES.md)：同一 Bot 的已接入渠道共用多级索引、条目和原文件版本。原作者可在同一会话让 Bot 发回已登记的任务原件，或自然地交代把它收入知识库，不必重开任务。记忆和 Skills 也按 Bot 实例共用。

- **持续处理任务**：渠道新消息直接交给同会话 Router 判断是否介入、回复和安排工作，每个事项只有一个执行会话。支持补充输入、等待、依赖和恢复；执行会话围绕当前目标在授权内继续取证和验证，不因没有现成验收环境就停止；提交阻断前对照原目标，区分同一环节的反复失败与独立路径，继续做能改变结论的获准检查。确实无法继续时提交证据和当前卡点，区分未到达的后续检查。Router 对照原目标判断还能否沿原会话推进，并向原渠道简短回报实际结果。完成和阻断共用同一文字回复入口，Host 给出当批结果对应的原消息绑定，实际回复时再次核对。按结果事件去重，结清与送达分别记录。Router 不代替执行排查。直接提交不需额外取证或行动的答案，并用实际结果或可靠回执核对需要验证的事项。已有事项的进度追问沿原任务查询和答复，不重复建任务或执行发布。恢复后的 Router 会主动复查挂起消息，根据任务实际安排或送达回执判断；上次暂缓的消息会在下次冷启动时带着最新证据再交给 Router，只有旧轮无副作用的原消息才可安全续办。任务完成不会自动授权后续动作。见 [任务模型](docs/SINGLE-TASK.md) 与 [排查和补问](docs/SINGLE-TASK.md#排查和补问)。
- **记住上下文**：Bot 共享 Markdown 长期记忆，支持记住、纠正、忘记和关键词检索，同时保留来源与读取权限。见 [长期记忆](docs/MEMORY.md)。
- **沉淀可复用技能**：Router 可直接维护学习 Skill；任务结束后另行复盘，依据证据提炼经验。学习只更新受管内容，不改写用户安装的正式技能或扩大执行权限。见 [自进化](docs/SELF-EVOLUTION.md)。 学习 Skill 首次生成和正文更新均实际加载内置 `skill-creator`，由受限 Pi 生成阶段产出正文，再经 Host 版本/来源校验后发布；复盘仍无工具。生成失败不回退直接拼装，不改写历史技能；creator 摘要和产出收据随版本保留。 记忆和 Skill 共用证据准入：同一事实有稳定权威来源时优先保留查询入口；有追溯价值或明确要求保留的已核实记录，可注明日期、范围和来源，单独存为历史快照，不写入 Skill。不保存未验证猜测、临时流水、失效重复内容、敏感原文或一次授权。任务复盘区分无效条目标识与无效证据引用；仅对确定未写入、没有跨遗忘的并发冲突按最新索引重试，不重放未知效果；记忆索引和 Skill 目录保留触发场景及关键动作，新任务按需打开适用正文。Skill 说明目标、主要环节、信息来源及正反场景，保留现场判断空间。安装操作者可显式开启事件局部维护与默认每周集中复盘；过时经验及随之失效的学习 Skill 分别留下撤销记录。自动维护默认关闭；复盘和维护沿用 Pi 路由的推理超时，维护输出格式错误按索引和计划分别留据。详见 [周期维护](docs/SELF-EVOLUTION.md#事件与周期维护)。
- **安排定时工作**：支持单次、固定间隔、每日、每周和五字段 cron，排期持久化，停机后恢复到期事项；周期事项合并漏过的轮次。见 [运行时说明](docs/RUNTIME.md)。
- **使用文件与工具**：提供文件读写、编辑、检索、Bash/PowerShell、后台作业、工作目录、待办及 HTTP 获取。Web 搜索和额外业务系统需单独配置，不随核心安装自动可用。
- **选择渠道与模型**：Web 与钉钉均为可选渠道。常规网页聊天的回复沿原来源回到同一网页，判断完成与否看实际投递回执；按原消息可查到关联的已完成任务，不需要重新建任务。可在同一 API 路由下管理多个模型，并分别为 Router 和任务执行选择模型（旧分诊配置仅保留历史）。见 [渠道](docs/CHANNELS.md)与[模型配置](docs/ops/shared-settings.md)。

通过本机 HTTP 续办原任务做隔离检查时，已认证的操作者可为本次补充关闭渠道结果回报；任务仍按原会话运行并留下结果，普通用户消息的答复不受影响。见 [本机 HTTP 任务入口](docs/HTTP-ROUTES.md#当前任务入口)。

任务执行会话默认采用[通用执行方法](docs/SINGLE-TASK.md#目标推进)：简单任务直接做，复杂任务在原会话规划结果、依赖和验法；遇阻按证据换策略，续办从未完成的环节继续。Pi 压缩长任务历史时保留验收要求、已核实进展和待查事项的引用。

## 快速开始

需要 **Node.js 24+**、**pnpm 11.25.0**，以及可用的模型服务和凭据。核心安装不需要 DWS CLI，也不默认启用 Web 或钉钉外发。

**新安装默认使用 `full`（完全访问）模式**：工具按启动 Bot 的操作系统账号权限执行，不提供工作区或进程隔离。先阅读下方[权限与运行边界](#权限与运行边界)，不要把未信任的任务或插件交给高权限账号运行。

```sh
git clone https://github.com/zzusp/night-bot.git
cd night-bot
pnpm install --frozen-lockfile
pnpm init:assistant --actor YOUR_OWN_ID --provider openai --model YOUR_MODEL --key-env OPENAI_API_KEY
```

- `YOUR_OWN_ID` 是你为本安装选择的稳定操作者标识；`YOUR_MODEL` 替换为服务商实际可用的模型 ID。
- 初始化生成独立实例标识与私有配置 `data/config/config.json`，再次运行会拒绝覆盖已有配置。
- 通过启动进程的 `OPENAI_API_KEY` 环境变量，或[凭据管理命令](docs/ops/shared-settings.md)，提供模型密钥。`--key-env` 只接收环境变量名称，不接收密钥正文。
- 自定义 API 可使用初始化参数 `--base-url` 和 `--api`；已有安装使用[统一配置命令](docs/ops/shared-settings.md)。初始化只创建配置与目录，不验证真实模型调用或渠道身份。

准备好凭据后启动核心服务：

```sh
pnpm start data/config/config.json
```

在另一终端检查健康状态：

```sh
curl http://127.0.0.1:18998/health
```

健康接口的 `recoveryIssueCount` 统计运行恢复异常，`taskAttentionCount` 单列等待输入、授权或外部条件的任务待处理项；普通等待不使核心健康降级，未知效果和真实执行故障仍保留告警。健康接口可达只表示服务可响应，不证明模型、任务或渠道已经验证通过。无界面集成可使用[本机 HTTP 接口](docs/HTTP-ROUTES.md)；需要聊天界面时，按下一节启用 Web。

### 启用 Web 控制台

Web 提供中文对话、Router 与任务执行记录、渠道管理、模型设置、权限审批和自进化记录。网页对话与任务详情底部都支持粘贴截图和添加文件；在任务详情补充内容会继续原任务的执行会话。任务列表每页 10 条，状态分为未在执行、执行中、已完成、已取消。见[日常使用](website/guide/usage.md)。它面向本安装的单个操作者，不是面向公网的多用户服务。执行记录保留全部工具名称、获权业务路径及常用执行工具的输入和文字结果；模型实际保存的可读思考可折叠查看，真实待办按事项及状态展示卡片。凭据继续脱敏，记忆/技能正文仍独立授权；同一次执行记录请求用一把共享记忆锁复核记忆和 learned Skill；同一条记忆正文只读一次，不同记忆条目限量并行读取，已显示的正文撤销或变化时旧页失效。认证的历史接口提供[资源复核与锁的分段耗时](docs/ops/web-console-local.md#执行记录性能排查)。不要求模型额外生成进展文字。 自进化列表按页读取元数据缓存，Skills 卡片总数与技能列表一致，支持 Windows 上连续强制刷新；刷新失败保留可核验的旧快照并明确提示，正文不进入该缓存。 历史使用统计以 SQLite 按源日志保存独立结果；每轮仍校验真实文件指纹，未变复用、变化重算，授权和资源版本变化会失效。数据库属于 `data/cache` 下的可重建缓存，不改业务账本；首次解码与文件哈希仍有成本。

任务详情和 Router 执行记录向上滚动时按消息身份续页，同一条用户记录不重复显示。页面通过 SSE 接收已脱敏的 Pi 实时输出，日志提交或断线重连后按游标补读。短暂提交等待期间，已显示的独立正文仍复核权限；通过后保留旧页，提交完成后沿原游标续读。通知交付前按会话、消息和版本索引检查有没有新来源，不再读取整个会话的来源正文。授权、通知顺序和未知发送回读规则不变，升级无需改配置或迁移账本。

在首次启动前执行以下命令。已有运行实例请先按[对应平台的运维流程](#部署与文档)正常停机，并沿用原 Web 渠道 ID 与操作者标识。

新消息不再调用分诊或自动发送收悉；旧分诊记录仅供内部恢复兼容，不提供 Web 展示。Router 新回复使用 Markdown，钉钉明确要求原生引用时保留纯文本引用。任务执行轮次正常收尾即显示「已完成」，未完成项仍写在结果里；「已取消」单列并显示原因。巡检核对运行状态，发现中断会通知所属 Router；由 Router 查原因并决定续跑原会话或取消。巡检还按结果事件 ID 核对回报：被隔离、等候超过 10 分钟、或已结清却没冻结通知的当前结果会出现在既有运行告警里，不改任务状态，也不自动补发。Web 任务列表只显示「未在执行」「执行中」「已完成」「已取消」四种状态，详情保留待调度、暂停和中断待核实，不提供中断的独立筛选或计数。Router 及任务执行记录只有调用没有结果时显示「结果未记录」，不把断开的旧调用显示成正在处理。中断轮没有正常结束时间时，Host 用原轮最后一条已提交会话记录估算执行时长，记入 SQLite，列表和详情显示「约」。执行记录正在提交时，页面保留上次已提交记录并显示局部提交状态，继续自动核对，不将正常提交窗口显示为接口失败。实时输出连接不可用时回到串行 HTTP 补读；实际不可读和撤权仍明确提示。

升级时，证据完整的旧任务也按同一口径补记「已完成」，保留原受阻结论，不重跑、不补发。详见[任务生命周期](docs/SINGLE-TASK.md#排查和补问)。

```sh
pnpm --dir packages/web-console install --frozen-lockfile
pnpm --dir packages/web-console build
node bin/night-bot-config.js data/config/config.json web --enabled true --host 127.0.0.1 --port 3080 --channel-id local-web --sender-id YOUR_OWN_ID --check
node bin/night-bot-config.js data/config/config.json web --enabled true --host 127.0.0.1 --port 3080 --channel-id local-web --sender-id YOUR_OWN_ID
pnpm start data/config/config.json
```

打开 `http://127.0.0.1:3080`，从启动日志指向的本机令牌文件读取访问令牌并登录。不要将令牌放入 URL、截图、聊天或源码。`--check` 只校验配置，不保存；实际保存后按返回的 `restartRequired` 正常重启。

Web 有独立依赖与构建，关闭浏览器不停止 Bot，禁用 Web 也不影响其他核心能力。详见 [Web 安装与排障](docs/ops/web-console-local.md)和[使用说明](docs/manual/web-console.md)。

**第一次交业务任务前，先配置[三处自定义提示词](#让-night-bot-按你的业务方式工作)。** 暂未接入支持职责配置的消息渠道时，先配两项会话工作原则，接入渠道后补写它的职责。

### 接入钉钉

安装并登录 DWS CLI 后，可通过 Web「渠道」或[统一配置 CLI](docs/ops/shared-settings.md)添加群聊或私聊。每个渠道实例只绑定一个会话，多个实例以不同 `channelId` 共存；每个实例可配置名称、职责和工作规范。

- 钉钉是可选插件，默认核心不会探测或启动 DWS。
- 新建渠道默认关闭外发，需要操作者明确授权；渠道开关不能替代任务本身的业务授权。
- 已发消息编辑经同账号精确回读后形成新来源版本；明确撤回生成墓碑并撤销旧来源授权，保留原接收进度与历史，不自动回滚已执行的操作。撤回后可直接正常停机；停机取消 Router 的在途记忆读取，已登记的撤回仍保留。
- 保存配置、实际连接、消息发送与独立回读是不同状态，不能用“保存成功”代替接入验收。启动、重连或恢复接收时，先按时间接纳并提交补拉范围，再放行实时消息；普通增量不阻塞实时。已暂停的钉钉群可由操作员按原暂停时刻[核查并补投已暂缓的消息](docs/ops/windows-local-runtime.md#暂停期间补投原暂缓消息)，不开放实时接收。历史补拉不完整或持久接纳出错时报告错误，不提前放行恢复期间的实时消息。
- 已绑定的私聊保留对端和登录账号侧的真人消息，仍进同一个会话。两边都发过消息后，Router 重启仍使用原对端的记忆绑定，继续处理已入库的消息。群聊和私聊均按原消息 ID 和发送回执识别 Bot 回声；回执未知时暂缓可能的回声，明确是其他发送者的消息继续接收，不自动重发。钉钉未实时推送的真人消息依赖历史补拉。
- 钉钉群聊的任务回执原生提及相关负责人或发起人；只有引用作者也在受众中才附引用。附件子消息不继承引用。
- PDF、Word 等附件可作为只读原件交给任务；Router 准备和执行器并发读取同一任务的同一材料时共用一次首次下载，后续读取仍校验文件与来源。原件可达不代表已安装对应解析器，单个材料上限为 8 MiB。

字段、身份绑定、附件和交付规则见 [渠道协议](docs/CHANNELS.md)；Windows 接入步骤见 [Windows 本机运行](docs/ops/windows-local-runtime.md)。

## 配置与扩展

Web 设置与 `night-bot-settings` 共用 Host 配置服务。模型目录支持同一路由下的多个模型，可为每个模型声明文本/图片输入能力或恢复目录默认，并保护仍被默认配置或角色引用的条目。API、模型目录等变更需正常重启，不会热切换已有执行会话。

```sh
# 查看运行中实例的设置和模型目录，不输出密钥。
node bin/night-bot-settings.js data/config/config.json show --live
node bin/night-bot-settings.js data/config/config.json model-list --live
```

- **模型与凭据**：配置 API 协议、地址、模型目录和角色模型，使用环境引用或凭据服务管理密钥。见 [统一配置命令](docs/ops/shared-settings.md)。需要指定每次模型重试的等待时间时，可按路由设置 [`retry.delaysMs`](docs/ops/kubernetes-deployment.md#模型重试间隔)。
- **技能**：默认发现随代码/镜像交付的[工作日志写作技能](skills/work-log-writing/SKILL.md)及脱敏示例、[skill-creator](skills/skill-creator/SKILL.md)，无需配置 `skillDirs`；已认证用户可用 `/skill:work-log-writing` 或 `/skill:skill-creator`。源码安装正常重启后生效，镜像安装需更新到包含本变更的镜像。仍支持 `skillDirs` 和私有安装目录，同名私有/自定义技能优先，不覆盖其文件。内置技能随代码更新，不进入私有技能学习快照；日报技能不改变独立定时日报提示。skill-creator 采用单执行会话流程，离线脚本需 Python 3（校验/打包另需 PyYAML，镜像已提供）；Claude CLI 触发率测量不属于默认能力。私有技能和业务素材仍不提交到代码仓库。学习技能在每次 Pi 资源刷新内共用批量授权视图，不跨轮复用；文件技能仍逐项检查当前文件和访问权限。
  独立会话的私有技能变更不刷新其他会话的目录；共享技能仍重新核验授权。已读技能或引用在执行中或重启间变化时，下一次模型请求会收到版本提示，正文仍由模型按当前权限显式重读。
- **渠道插件**：通过 `channelPluginDirs` 与 `channelPlugins` 接入其他消息渠道。插件须遵循认证身份、生命周期和能力合同。见 [插件接口](docs/CHANNEL-PLUGINS.md)。
- **工具插件**：可信部署配置可挂载额外浏览器、搜索、数据库等能力。插件与 Host 同进程运行，不是沙箱；不会从普通群消息自动加载代码。

Router 和任务执行的活跃 Pi 会话沿用已提交的日志前缀，提交时只检查并落盘新增记录或分支切换；重新打开、恢复和离线核验仍严格检查磁盘日志。磁盘格式不变，无需迁移。

官方会话工厂发布前，会按耐久默认选择、显式运行时/记忆模型选择及当前角色模型选择预加载所需 Pi 协议模块，只做本地导入，不读模型凭据、不发探测或推理请求。首次模块加载成本移到启动阶段；无效模型配置仍保留现有延迟诊断。Router 性能使用现有 `/state/performance` 查询，按真实 `sessionId` / `groupId` 返回 `runtimeOwner: conversation-router`（旧分诊观测只作历史回查） 及 `phaseMs`（次数、总量、最大值、p50/p95、失败次数），无需创建任务。阶段覆盖会话准备、资源读取/SDK reload、输入接纳、请求准备、提交和收尾；只记录元数据。嵌套及并行阶段不可相加，SDK 模型尝试次数不代表 HTTP 请求数；旧记录缺少分项时返回空集合，不回填推测耗时。

Router 的上下文目标为 472,000 tokens，实际取该目标和模型真实窗口的较小值；完整轮次在 60% 水位尝试可取消的后台摘要，80% 由 Pi 原生前台压缩兜底。大消息预检包含系统提示、工具和输出余量；无法容纳时返回 `PI_CONTEXT_INPUT_TOO_LARGE`，保留耐久待办而不截断正文。重复输入不触发摘要，Router 续办先检查全部新输入再领取检查点。详见[后台压缩合同](docs/BACKGROUND-COMPACTION.md)。

Router 将适用的长期行为指令单独必载，普通偏好/背景只载索引；同轮追加来源后，在下一次模型请求前按认证作者刷新。Router 默认获得现有 SQLite 的分页任务索引及相关回复索引，可用 `resident_task_query(detail=progress)` 按需查看严格已提交的执行记录，用 `resident_reply_query` 核对冻结正文与当前送达状态，包含任务在原会话提出的问题及任务状态回复，避免同一问题换措辞重复发送；不会为查询唤醒任务或补发消息。手动、自动、overflow 与后台候选统一使用 Pi 原生角色摘要，详细事实仍以原账本为准。见[渠道上下文](docs/CHANNELS.md#当前上下文与按需查询)和[长期行为指令](docs/MEMORY.md#独立长期行为指令)。

已有记忆布局升级须先正常停机并执行[离线检查与迁移](docs/MEMORY-MIGRATION.md)，未升级时新版拒绝启动。本地操作者明确不备份时，v3→v4可显式使用 `--no-backup`；保留中断续写与冲突校验，但不提供旧格式回滚。

## 权限与运行边界

权限模式由可信安装操作者通过 CLI 或认证 Web 设置，模型和普通渠道成员不能自行升级权限。

渠道新来源直接入 Router，不再创建分诊轮次、分流阶段或自动收悉。每批至多 15 条，来源/版本及原队列恢复校验保持，见 [CHANNELS](docs/CHANNELS.md#渠道直入-router-与历史分诊)。Bot 面向人的回复默认按 [ELI5 原则](docs/CHANNELS.md#对外回复的信息取舍)写：先答对方问的事，用日常话把结果说具体。没明确要明细就只说结论和下一步，复杂问题也一样；多问逐项简答。不把排查记录、免责声明或自辩写进回复。发前对照最新原话和关联任务，只留影响所问结论或下一步的事实；有实际卡点或待查问题就说具体缺什么、接下来查什么。回复沿用原有入口；Host 仍校验安全、来源和受众，旧冻结回复保持原样。

Router 把已有任务的状态、进度和结果追问交给异步只读查询：同会话可并行，全实例同时执行两条，超出的在后台等待，Router 继续处理其他消息。找不到问题指向的同会话任务时，请用户补任务名或链接，不用相似任务代答。不会唤醒原任务。见[临时任务只读查询](docs/CHANNELS.md#router-的临时任务只读查询)。

渠道 Router 遇到模型超时、Pi 重试仍失败时，会留下待续办记录。现有恢复流程会唤醒原 Router，由它判断是否需要补回复；不需要用户再发一条消息，不重跑任务。详见 [Router 恢复](docs/CHANNELS.md)。

Router 在开轮或轮末刷新资源失败时会停止当轮请求。下一条仍待接纳的输入先按原阶段重新校验并加载资源，通过后沿原会话处理；技能授权仍在变化时，原批次保留并按既有退避重试。不重放已接纳的输入或已执行的工具。

崩溃留下的真实空 `contexts.json.lock` 仅由 Host 在取得独占安装租约、确认没有恢复中标记且尚未启动渠道写者时回收；活跃、非空或链接锁不强抢。原 Router 已接纳批次若仅缺 `resident_router_settle` 结果，Host 校验原批次/当前代际后，以原幂等键完成或读取真实 SQLite 结清事务，再将实际结果写回同一 Pi 会话；不运行模型或重放其它工具。已提交结清但缺结果的空闲会话在下一事件打开时先对账，不扫描加载全部历史。

正常停机中止的 Router 生成沿原 Pi 历史安全续轮，较新取消/延期输入先耐久接纳再推理；原输入及已完成效果不重放。未知效果、来源/owner 变化或恢复批次超限仍保留告警；模型 error、正常 stop 或已完整提交成功只读任务查询结果的未结批次不会自动重试，操作者可通过 `node bin/night-bot-router.js CONFIG inspect CONVERSATION_ID` 取得原批次 proposal，再按 [runbook](docs/ops/windows-local-runtime.md#router-模型错误的显式续办) 检查并显式续办。续办控制消息提供准确事件ID及结清工具要求，纯文字回复不代表事件已消费。旧分诊收悉不代表后续任务已完成。部分结清批次中的已配对只读排期查询失败、仅涉及原批次且不提交巡检评审的结清失败，可在独立新消息到达后走隔离交接；旧调用不会重放。整批没有结清时，若原生检查点和冻结事件都能验证且有独立新来源，Host 留置原批次并投递后续消息；不会把留置记成已处理。恢复合同见 [CHANNELS](docs/CHANNELS.md#已接纳未结批次的安全续办)。

Router 对所属会话的执行 session 拥有完整调度权，创建、启动、停止、解除等待及取消/完成后的重新唤起不要求原消息作者或安装操作者补调度许可；来源保留真实追溯，旧交接记录的历史来源或任务 ID 不锁住后续调度，停止仍实际排空原 owner。已结清的旧未知效果只永久禁止原具体调用重放，不再要求后续独立调用或完成结果匹配专门的新目标授权。尚未结清时也能唤起原会话核验，但不能重放旧效果或宣称成功。工具本身继续遵循当前权限模式、秘密和业务效果边界。[原 new-action 入口](docs/EFFECT-ACTION-AUTHORIZATION.md)保留为可选人工运维方式，不是续办前置。Bot 的旧回复和任务摘要不会产生新审批要求；真实审批和实际权限限制仍有效。

执行会话排空失败会持久保留故障，任务列表归入「未在执行」，详情显示会话失败并提示核实未决作业或副作用；`drained=false` 不再单独冒充仍在推进。此展示不改变排空证明、待处理输入或原调用禁止重放保护。已排空的技术等待区分模型超时、输入超限、供应方明确内容策略拒绝、正常返回但未提交结果。Router 可复用原结果回复入口向发起人说明本次停止；诊断不会自动重试或补发旧记录，详见[任务输入与重试](docs/PI-TASK-INPUT-AND-RETRY.md#retry-behavior)。

Pi 文件工具的匹配错误及底层原子锁内的观察/版本拒绝，在受信执行已结束且可证明尚未开始发布时保留原错误，允许读取后独立纠正；写后结果丢失仍保持未知。旧未知调用不会被新代码追认为无效果；对账校验原执行者排空与后续核验执行者的最新切点；仅原生冷丢失 shell 可使用精确绑定的离线作业对账收据替代缺失的原证明，仍须真实核验排空和操作者读回。核验正常完成后可对账旧效果，原完成结果和控制状态不变。见[未知效果对账](docs/EFFECT-RECONCILIATION.md)。

| 模式 | 行为与当前范围 |
| --- | --- |
| `full` 完全访问 | **新安装默认值，也是当前交付重点。** 按启动进程的 OS 账号权限执行，不提权，不隔离同账号可访问的文件、凭据或进程。Host 的来源绑定、授权、审计、取消和防重放仍保留。 |
| `ask` 请求批准 | 需要扩大范围的动作进入单次人工审批。合同与配置入口保留，受限执行尚未完成交付验收。 |
| `auto` 帮我批准 | 需要批准的动作由无工具模型审查，无法确定或技术失败转人工。受限执行同样尚未完成交付验收。 |

已有配置显式保存的 `ask` / `auto` 保持不变，不会因默认值变化而改成 `full`。受限后端不可用时拒绝执行，不自动降级为完全访问。

- Pi SDK 本身不提供 Night Bot 的权限系统；应用校验和操作系统隔离是不同边界。`full` 的任意 shell 可访问同账号可读的 Host 私有文件，不能把应用接口校验当作进程隔离。
- 核心管理 HTTP 只监听 loopback。Web 的容器监听也要求固定 Origin、令牌、会话及 CSRF 校验，宿主端口仅发布到 loopback，不应直接暴露公网。
- Linux 受限 shell/模型进程需要可用的 bubblewrap 等隔离能力；Windows 受限执行与撤权仍有未完成项。macOS 已验证安装、服务和部分无命令任务，命令执行及长轮次续办仍有未通过项。平台验收不能互相替代。
- 发送或执行结果未知时保留现场并核对原回执，不自动重发或重放。真实模型、厂商账号与渠道交付需在目标运行环境单独验收。

当前权限范围和平台限制见[运行验收入口](docs/acceptance/resident-conversation-routing/goal.md)及各平台运维文档。

## 数据与备份

应用自有数据保存在安装目录的 `data/`，业务工作区与产物默认在 `data/workspaces/`，备份在 `backups/`。这些目录均被 Git 忽略；升级代码必须保留数据，不复制他人的凭据或私有技能。

任务账本在 `data/state/tasks.sqlite.owner.sqlite` 独立连接上持有 SQLite OS 排他锁，进程退出即释放；不删除锁文件、不按超时抢占。新版残留 owner 不再因容器 PID 复用误拦启动，旧版 PID-only owner 仍保守拒绝存活 PID；旧记录的停机恢复边界见 [Kubernetes 运维](docs/ops/kubernetes-deployment.md#数据库占用故障)。事务 owner fencing 与副作用 unknown/no-replay 规则保持。

每个任务的材料、工作文件、冻结产物、Pi 会话和复盘集中在 `data/workspaces/tasks/<taskId>/`。共享 SQLite 仍是运行时权威，`task.json` 由后台队列投影，不能当作可重放命令。任务启动仍会在打开会话前校验档案路径和会话归属。

普通停机目录不等于已校验的可迁移备份。跨路径迁移须显式离线封存和核验，恢复默认暂停并保留交付防重门禁。详见 [数据布局](docs/DATA-LAYOUT.md)和[任务备份与恢复](docs/TASK-ARCHIVE.md)。本项目不提供原 DSH 插件历史数据导入。

pnpm install --frozen-lockfile

pnpm test               # 默认测试组，随后运行 pnpm check
pnpm test:domain

pnpm --dir packages/web-console test

## 报错反馈取证

Web 执行历史每次读取都核对当前日志字节；仅复用字节完全相同、已严格验证且完整提交的 Pi 快照，按原始字节总量限制为 32 MiB，进程关闭即清空。调用方取得独立副本，秘密仍按每次请求的当前集合脱敏，live 只投影临时增量。该缓存不修改 journal、任务状态或未知效果防重放规则。Router 的来源版本判断复用既有会话/消息/版本索引，不再为每条待处理记录重读并解码全部来源；范围和最新版本校验不变。实时轻查询的 proof 绑定底层持久化身份，Cordis 服务门面变化不使同一权限范围的有效 proof 失效。

Web 报错反馈在操作者明确同意后启动只读 Pi 调查；标题与描述中的原文片段可用于定位消息、业务任务和原生定时事项，不要求先找到最近的创建消息。查询失败会说明固定错误原因与纠正方法，历史消息和候选目录可按返回游标续查；无匹配、日志空计数或读取失败都不表示没有记录或错误。关联会话可先筛选工具失败或 Skill 证据再分页，长任务后段也能查到；文件读结果、版本提醒和可信读回执分别显示；任务技能摘要比较同名调用的成功结果、新提醒和 Pi 上下文仍保留的旧提示，帮助区分重新触发、旧提示重复处理和加载失败；不输出私有提示原文。调度证据区分单次/循环并展示保存的时间参数，指令内的停止条件仍须另外核实。源码整份脱敏后分页，长行可按字符续读；源码搜索与公开日志字段使用单次调查内有界快照，私有日志正文不参与 query。文件按已打开句柄核验范围，轮转和不可读项明确记录缺口。模型失败时，若已取得证据，保留标明未完成的草稿；若未取得证据，页面显示可公开的失败原因和诊断编号。草稿以原因判断开头，只保留最关键的核对事实，原问题描述放在诊断后；没有可核对的引用、模型输出截断、预算摘要失败或未附引用都会明确标注，最终预览为问题描述预留完整空间。证据明细默认折叠，只在本次预览中查看，不随正文复制或提交。调查只生成可编辑草稿，发布 Issue 仍需预览后单独确认；详见 [报错反馈手册](docs/manual/error-feedback.md) 与 [Web 运维](docs/ops/web-console-local.md#报错反馈现场取证)。

AI 调查遇到暂时性模型故障或取证读取繁忙时，对当前请求最多尝试 3 次，不重新开始整轮调查。调查最终失败时，Host 日志只记录调查编号、阶段、固定错误码和耗时，不记录问题正文或原始异常。

## 来源与许可

Night Bot 使用 Pi SDK，早期移植来源为 `HiQ-AI/dingtalk-dsh-assistant@93e431a`，Web 设计参考 [BoardUI](https://github.com/BoardUI/boardui)。具体来源、版本、保留实现及许可见 [THIRD_PARTY.md](THIRD_PARTY.md) 和 [`licenses/`](licenses)。

仓库保留原 [MIT LICENSE](LICENSE)，但移植模块并未因此自动改授 MIT。当前根包标记为 `private: true`、`UNLICENSED`，不作为 npm 发布包；请按来源清单核对使用与再分发条件。

原生作业的已提交终态保留有界模型可见输出（默认沿用 16 KiB 终态保留预算，遵守作业自身更小的输出上限）；不保存 observer log。执行者释放或进程重启后，原会话可按 job ID 用 `job_output` 回读快照，`job_kill` 返回已结束，不重跑 producer；`job_list` 仍只列当前注册作业。截断会明确提示，完整输出仍需保存为工作区文件。旧收据没有快照时只能回读可信终态并明确输出不可恢复；升级不会补造旧输出。快照属于私有运行数据，不得入 Git；含新字段的 journal 不交旧版本打开。

丢失终态的旧 shell 作业不阻止原会话接收新输入、推理或只读核验，也不自动重跑。需要结清旧作业时，核对真实进程与效果，再用离线操作者 `night-bot-jobs` 的 `inspect` / `close --check` / `close`；它只记录可能存在的部分效果和原调用禁止重放，不伪造成功或旧资源已排空。见 [效果对账](docs/EFFECT-RECONCILIATION.md#丢失终态的原生-shell-作业)。
